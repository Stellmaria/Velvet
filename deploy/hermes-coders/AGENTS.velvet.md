# Проектный контракт Hermes Coder: Velvet

Личность агента задаётся в `SOUL.md`. Этот файл содержит только проектные правила и процедуры.

## Граница проекта

- Работай только над `Stellmaria/Velvet` в каталоге `/workspace`.
- Не переключайся на Romatic Club, Max или другой репозиторий.
- Не продолжай старую задачу, если пользователь назвал другую задачу или другой объект.
- Перед изменением зафиксируй репозиторий, ветку, задачу, затрагиваемые файлы и критерий готовности.
- Сначала прочитай репозиторный `AGENTS.md` и обязательную проектную документацию.
- Если нужного объекта нет в `/workspace` или read-only базе Velvet, остановись и сообщи точную причину.

## Git

- Не работай напрямую в `main`.
- Создавай отдельную ветку для каждой задачи.
- Не выполняй force-push, reset чужих веток, удаление веток или merge.
- Перед коммитом показывай краткий diff, запускай релевантные тесты и проверяй `git status`.
- Не включай секреты, production env, дампы, токены и диагностические архивы в Git.
- Для одной оркестрированной задачи создавай не более одной ветки и одного pull request.

## База данных

- Production PostgreSQL доступен только read-only ролью.
- Не пытайся обходить `default_transaction_read_only`, менять роль или подключаться владельцем базы.
- Сначала изучай текущую запись и схему, затем готовь миграцию или контролируемое изменение в ветке.
- Не редактируй уже применённые миграции.
- Production-изменения данных и применение миграций выполняются отдельно после проверки и явного разрешения владельца.

## Безопасность

- Разрешённая область записи: `/workspace` и собственный `/opt/data`.
- Не ищи секреты и не исследуй соседние контейнеры, production volumes, Docker socket или системные каталоги.
- Не запускай Docker, systemd, deployment, restart, update или rollback.
- Не запускай платные генерации и внешние действия без необходимости задачи.

## Оркестрированные задачи

- Задача с заголовком `ОРКЕСТРИРОВАННАЯ ЗАДАЧА` поступает от Каэля через закрытый Runs API.
- Строго сохраняй переданный Task ID и не смешивай его с другой работой или Telegram-сессией.
- Подготовь код, тесты, документацию, отдельную ветку и один PR.
- Не сливай PR и не выполняй production-действия.
- В финале обязательно верни отдельными строками:

```text
STATUS: completed|blocked|failed
BRANCH: <branch-or-none>
PR: <url-or-none>
TESTS: <commands-and-result>
BLOCKER: <exact-blocker-or-none>
```

## Модельная маршрутизация

Основная модель — `gpt-5.4-mini`. Для сложной архитектуры и больших расследований используй `terra`; `luna` является резервом. Не меняй модель без причины, связанной со сложностью задачи или ошибкой провайдера.
