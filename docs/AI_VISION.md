# Глубокий ИИ-анализ изображений

> **Статус Ollama: legacy/deprecated.** Локальный Ollama-контур отключён и не
> используется в production-конфигурации Velvet. Старые классы, переменные и тестовые
> адаптеры временно сохраняются только для чтения прежних настроек, старых очередей и
> безопасной миграции. Серверный preflight запрещает `AI_TEXT_PROVIDER=ollama`,
> `AI_VISION_PROVIDER=ollama` и Ollama в маршрутах VL-каскада.

Текущий production-контур использует облачные OpenAI-совместимые модели через
`AI_VISION_PROVIDER=openai_compatible`. Анализ не сопоставляет лица. Он выделяет
тему, жанр, эпоху, локацию, окружение, предметы, одежду, действие, композицию,
свет, палитру и настроение.

Пример: разные персонажи в салуне, пустыне и на ранчо с ковбойскими признаками
получают общий смысловой профиль `western` и могут быть предложены как сет
«Дикий Запад».

## Production-конфигурация

Минимальная облачная конфигурация:

```dotenv
AI_VISION_ENABLED=true
AI_VISION_PROVIDER=openai_compatible
AI_VISION_BASE_URL=https://byesu.com/v1
AI_VISION_MODEL=provider-model-id
AI_VISION_API_KEY=
AI_VISION_TIMEOUT_SECONDS=300
AI_VISION_MAX_ATTEMPTS=3
```

`AI_VISION_API_KEY` может быть пустым, когда используется общий `BYESU_API_KEY`.
Для production должны быть заданы положительные input/output цены, чтобы бюджетный
guard мог оценить запрос до отправки провайдеру.

## VL-каскад

Velvet поддерживает три роли:

- `FLASH` — основной дешёвый и быстрый анализ;
- `PRO` — повторный анализ при низкой confidence или ошибке Flash;
- `SENSITIVE` — отдельный маршрут для явно выбранного чувствительного режима либо
  после отказа стандартной модели.

Пустые `provider`, `base_url` и `api_key` роли наследуют базовые `AI_VISION_*`.
Каждая облачная роль должна иметь model ID и тарифы:

```dotenv
AI_VISION_FLASH_MODEL=
AI_VISION_FLASH_INPUT_RUB_PER_1M=
AI_VISION_FLASH_OUTPUT_RUB_PER_1M=

AI_VISION_PRO_MODEL=
AI_VISION_PRO_INPUT_RUB_PER_1M=
AI_VISION_PRO_OUTPUT_RUB_PER_1M=

AI_VISION_SENSITIVE_MODEL=
AI_VISION_SENSITIVE_INPUT_RUB_PER_1M=
AI_VISION_SENSITIVE_OUTPUT_RUB_PER_1M=
```

Порог перехода к Pro задаётся через
`AI_VISION_CASCADE_CONFIDENCE_THRESHOLD`. Версия системного промта фиксируется в
`AI_VISION_PROMPT_VERSION`, чтобы результаты можно было воспроизводить и сравнивать.

## Изображение → промт

Операция принимает фотографию или image-документ и формирует генеративный промт
в редакционном формате `Vᴇʟᴠᴇᴛ Sɪɢɴᴀᴛᴜʀᴇ`.

Результат использует постоянную структуру канала:

- `ВАЖНО` и `СТРОГО`;
- `Технический блок`, `Суть`, `Композиция и поза`;
- отдельные разделы для лица, взгляда, рук, тела и волос;
- локацию, фон, освещение и словесную цветовую палитру;
- дополнительные генеративные теги;
- расширенный `Negative prompts` под конкретный кадр;
- отдельный блок `PALETTE` из 5–6 приблизительных HEX-цветов.

Редакционный стиль не должен менять факты изображения. Операция не удаляет
видимую одежду, не добавляет художественную наготу, не придумывает личные
референсы, имена или татуировки и не навязывает формат `9:16`.

## Очередь и хранение результатов

- существующие и новые изображения получают запись в `media_ai_profiles`;
- фоновый процесс анализирует изображения последовательно;
- исходное изображение уменьшается максимум до 1280 пикселей по длинной стороне;
- структурированный JSON-профиль сохраняется в PostgreSQL;
- поиск сетов сравнивает профили независимо от имени и внешности персонажа;
- бот создаёт предложения, а окончательный состав выбирает администратор;
- общий промт хранится один раз на весь подтверждённый сет.

Queue mode включается после одиночного cloud smoke-test:

```dotenv
AI_VISION_QUEUE_ENABLED=true
AI_VISION_BATCH_PLAN_TTL_SECONDS=900
```

## Что остаётся отдельно

Поиск точных и почти точных дублей продолжает использовать visual fingerprint.
ИИ-анализ не заменяет этот механизм и не удаляет файлы автоматически.

## Legacy Ollama

Следующие элементы считаются устаревшими:

- provider `ollama` в text и vision settings;
- локальные Qwen VL/LLM bundles;
- Supervisor recovery и Windows-диагностика Ollama;
- compare/fallback-маршрутизация, рассчитанная на локальную VRAM.

Они не должны появляться в `.env.server`. Удалять совместимый код следует
отдельной миграцией после подтверждения, что в PostgreSQL и очередях нет старых
payload и ни один рабочий deployment больше не читает Ollama-переменные.

## Отключение анализа

```dotenv
AI_VISION_ENABLED=false
AI_VISION_QUEUE_ENABLED=false
```

Архив, поиск дублей и безопасные эвристики продолжают работать без VL-анализа.
