# Сессия: аварийный перезапуск Supervisor при зависшем operation lock

- Дата: 2026-07-28
- ID: `2026-07-28-supervisor-emergency-restart`
- Линия/фаза: Supervisor / remote recovery
- Статус: `завершено`
- Ветка: `agent/supervisor-emergency-restart`
- Базовый commit: `6eb01d2703a3888649c085e5f7fdc094768bc1fa`

## Перед началом

### Цель

Сохранить удалённый путь перезапуска самого Supervisor, даже если общая системная операция зависла и удерживает `_operation_lock`.

### Исходный контекст

Команда безопасной консоли `ollama list` осталась в состоянии `running` более двадцати минут. Все обычные операции, включая self-restart и self-update, использовали один общий lock и отвечали `Уже выполняется другая системная операция`. В результате Supervisor не мог удалённо перезапустить сам себя.

### Планируемый объём

- разрешить обычному self-restart обходить общий operation lock;
- оставить self-update сериализованным и запрещённым при активной операции;
- сохранить передачу перезапуска независимой задаче Windows Task Scheduler;
- добавить regression-тест зависшего lock.

### Критерии готовности

- `schedule_supervisor_restart(update=False)` работает при уже занятом `_operation_lock`;
- `schedule_supervisor_restart(update=True)` по-прежнему возвращает `OperationConflict`;
- аварийный restart не запускает shell и не меняет checkout;
- CI проходит.

### Риски и ограничения

Исправление не может быть загружено уже зависшим старым процессом: его update и restart заблокированы тем же lock. Для первого восстановления всё ещё требуется внешний перезапуск Windows-задачи, процесса Supervisor или компьютера. После установки hotfix повторное зависание можно будет устранить штатной кнопкой `Рестарт Supervisor`.

## После завершения

### Фактически сделано

- plain self-restart больше не захватывает общий `_operation_lock`;
- restart передаётся существующей bootstrap-задаче Windows и прерывает зависшую операцию вместе с текущим процессом;
- self-update сохранил прежнюю блокировку, поскольку обновлять checkout параллельно другой операции небезопасно;
- сообщение операции явно помечает аварийный характер перезапуска;
- добавлены два regression-теста: restart проходит при занятом lock, update отклоняется.

### Миграции и совместимость

Миграции не требуются. HTTP-маршрут и Telegram-кнопка не меняются: существующий `POST /v1/self/restart` получает восстановительное поведение после обновления Supervisor.

### Проверки

Полный tests workflow, type check и project notes contract запускаются в PR.

### PR и commit

Ветка `agent/supervisor-emergency-restart`; PR создаётся после записи изменений.

### Незавершённое

Текущий production-процесс с уже зависшим lock нельзя обновить через него самого. Нужен один внешний перезапуск через Windows, AnyDesk/RDP или физический доступ.

### Следующий шаг

После внешнего восстановления обновить Supervisor до hotfix. В дальнейшем кнопка `Рестарт Supervisor` будет работать независимо от зависшей обычной операции.
