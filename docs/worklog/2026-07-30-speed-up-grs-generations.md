## Перед началом

### Цель

Сократить задержку генераций Nano Banana через GRS AI без автоматического запуска второй платной модели, без ухудшения качества выбранной модели и без блокирующей проверки баланса перед отправкой задачи.

### Исходный контекст

Friendly worker перед каждой GRS-генерацией запрашивал баланс провайдера. Клиент баланса последовательно пробует несколько endpoint и использует общий сетевой timeout, поэтому недоступность GRS balance API могла задержать отправку уже подтверждённой генерации. Telegram-референсы скачивались и загружались по одному, а повторное использование подготовленного URL работало только внутри одной provider-кампании.

### Планируемый объём

- убрать автоматические запросы баланса из запуска и terminal notification;
- добавить отдельную owner-only кнопку баланса GRS;
- сократить polling результата до двух секунд;
- сократить внутренний интервал media worker до одной секунды;
- готовить независимые референсы параллельно с ограниченной конкуренцией;
- повторно использовать недавно загруженные референсы через краткоживущий in-memory кэш;
- инвалидировать кэш после provider-ошибки expired/download URL;
- сохранить исходную модель, качество и единственную платную provider-задачу;
- добавить регрессионные тесты.

### Критерии готовности

- генерация стартует без запроса GRS credits;
- баланс доступен отдельной кнопкой и не влияет на очередь;
- до трёх референсов скачиваются и загружаются одновременно;
- порядок image URLs совпадает с порядком выбранных референсов;
- повторное использование того же Telegram-файла не требует новой загрузки в пределах TTL;
- протухший URL удаляется из общего кэша;
- Banana 2 и Banana Pro не запускаются автоматически последовательно или параллельно;
- расчёт GRS отображает тарифы GRS, а не цену одного кредита Kie;
- CI проходит.

### Риски и ограничения

- основная очередь и вычислительное время GRS остаются под контролем провайдера;
- кэш существует только в памяти процесса и очищается при перезапуске;
- временные URL сохраняются на 20 минут и удаляются раньше при provider-ошибке ссылки;
- увеличение частоты idle polling media queue с трёх до одной секунды добавляет несколько лёгких запросов PostgreSQL в секунду;
- реальное ускорение одной Pro-генерации не гарантируется в два раза, если основная задержка находится внутри GRS.

## После завершения

### Фактически сделано

- автоматическая проверка GRS balance удалена из критического пути генерации и сообщения об исчерпании кампании;
- добавлен отдельный экран `Баланс GRS AI` с ручным обновлением и timeout восемь секунд;
- стоимость GRS считается по внутренним тарифам Nano Banana 2 и Pro, а не по цене Kie credits;
- polling provider status ограничен двумя секундами;
- интервал запуска media workers сокращён до одной секунды;
- подготовка референсов выполняется конкурентно, максимум по три одновременно;
- добавлен in-memory LRU-подобный кэш на 256 URL с TTL 20 минут;
- кэш использует Telegram `file_unique_id`, MIME type и размер файла;
- provider-ошибка expired/download URL удаляет соответствующие URL из общего кэша;
- сохранены порядок референсов, существующая economy campaign и защита от платных дублей;
- добавлены тесты параллельной подготовки, повторного использования URL и расчёта стоимости GRS.

### Миграции и совместимость

Миграции PostgreSQL не требуются. Формат provider payload, model aliases, существующие callback data и записи очереди не меняются. Добавлен новый callback action `grs_balance`. Серверные переменные окружения остаются совместимыми.
