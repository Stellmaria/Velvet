## Перед началом

### Цель

Устранить повторяющуюся ошибку asyncpg при сохранении отредактированных постов канала, когда Telegram `edit_date` приходит как Unix timestamp, а база ожидает `datetime`.

### Исходный контекст

`parse_channel_post` передавал `message.date` и `message.edit_date` в `ParsedChannelPost` без нормализации. В рабочем update поле `edit_date` имело тип `int`, поэтому аргумент `$5` запроса `channel_posts.edited_at` отклонялся asyncpg.

### Планируемый объём

- добавить совместимый нормализатор Telegram datetime/Unix timestamp;
- устанавливать его до загрузки Telegram router-ов;
- сохранить поддержку уже распарсенных `datetime`;
- добавить регрессионные unit-тесты;
- не менять схему PostgreSQL и существующие данные.

### Критерии готовности

- integer timestamp преобразуется в timezone-aware UTC `datetime`;
- обычные `datetime` не изменяются;
- `None` остаётся допустимым для `edit_date`;
- analytics ingest больше не передаёт число в TIMESTAMPTZ;
- CI проходит.

### Риски и ограничения

Посты, которые не сохранились во время ошибки, автоматически не восстанавливаются. Следующее редактирование или повторный ingest сохранит актуальную версию. Исправление устанавливается в стандартной точке запуска `velvet_bot.app.run_application`.

## После завершения

### Фактически сделано

- добавлен `velvet_bot.app.channel_analytics_datetime_compat` без нового корневого модуля;
- Unix timestamps преобразуются через `datetime.fromtimestamp(..., timezone.utc)`;
- нормализуются и `date`, и `edit_date`;
- совместимость устанавливается до импорта application bootstrap;
- добавлены тесты integer timestamp, обычных datetime и запрета boolean;
- обновлена инвентаризация Python-файлов.

### Миграции и совместимость

Миграции PostgreSQL не нужны. Существующие записи не изменяются. API команд и формат таблиц остаются прежними.

### Проверки

Добавлены unit-тесты `tests/test_channel_analytics_datetime_compat.py`. Первый полный прогон подтвердил работу новых тестов, но потребовал перенести модуль из корня `velvet_bot` внутрь существующего пакета `app`, чтобы сохранить архитектурный лимит корневых модулей. Финальный CI запускается повторно.
