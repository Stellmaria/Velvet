## Перед началом

### Цель

Разрешить до четырёх одновременных генераций Kie, увеличить лимит попыток с трёх до одиннадцати и добавить владельцу экран живого баланса аккаунта Kie с фактическими списаниями `creditsConsumed`, очередью и локальной себестоимостью.

### Исходный контекст

После PR #365 бот поддерживал Grok Imagine v1, Seedance 1.5 Pro и Wan 2.6, но один периодический worker обрабатывал только одну платную задачу за раз. Генерации ставились в очередь с `max_attempts=3`. Usage ledger уже сохранял `consumed_credits` из ответа Kie, но интерфейса для просмотра живого остатка и накопленных списаний не было.

### Планируемый объём

- добавить настройки `KIE_MAX_CONCURRENT_GENERATIONS` и `KIE_GENERATION_MAX_ATTEMPTS`;
- зарегистрировать несколько независимых Kie worker-слотов с уникальными worker id;
- при захвате Kie-задачи повышать сохранённый `max_attempts` до настройки runtime;
- увеличить повторы скачивания референса, результата и Telegram-доставки до одиннадцати;
- реализовать официальный `GET /api/v1/chat/credit`;
- добавить экран `Баланс Kie · очередь`;
- показать live-кредиты, сумму `creditsConsumed`, локальные рубли, очередь и последние списания;
- сохранить бюджетные reservations и существующий dedupe платного запуска.

### Критерии готовности

- четыре Kie-задачи могут находиться в статусе running одновременно;
- один queue task не захватывается несколькими слотами;
- Kie-задача получает `max_attempts=11` при первом захвате;
- сетевые операции доставки повторяются до одиннадцати раз с ограниченным backoff;
- владелец видит текущий баланс кредитов Kie и сохранённые списания;
- tests, type check, Docker build и project notes contract проходят.

### Риски и ограничения

- Kie Common API возвращает баланс в кредитах, а не в рублях или долларах;
- рублёвая себестоимость остаётся локальной оценкой по `.env`;
- `creditsConsumed` зависит от того, вернула ли его конкретная provider-задача;
- повтор whole-task после неопределённого сетевого ответа createTask теоретически может создать вторую provider-задачу, если Kie принял первый запрос, но ответ потерялся;
- четыре параллельных дорогих Wan-задачи быстрее расходуют аккаунт, поэтому budget guard остаётся обязательным.
