## Перед началом

### Цель

Позволить владельцу восстановить локальный Ollama vision с телефона через безопасную консоль Supervisor без доступа к произвольному PowerShell.

### Исходный контекст

Pose extractor успешно создавал AI job, но обе модели завершались `WinError 10061`, потому что Ollama не слушал `127.0.0.1:11434`. Одновременно рабочий процесс Supervisor продолжал передавать дочернему боту устаревшие `AI_VISION_MODEL=hf.co/...GGUF` и `AI_VISION_COMPARE_MODEL=qwen3-vl:8b`.

Текущий allowlist содержал только `ollama list`, поэтому удалённо нельзя было запустить сервер, исправить рабочий `.env`, скачать официальную vision-модель и проверить capability.

### Планируемый объём

- добавить отдельный модуль безопасного восстановления Ollama;
- разрешить только фиксированные действия без пользовательских аргументов;
- атомарно изменять только разрешённые `AI_VISION_*`;
- запускать `ollama serve` отдельным локальным процессом;
- скачивать только `qwen3-vl:4b`;
- проверять capability `vision` через `/api/show`;
- зарегистрировать отдельные диагностические и восстановительные команды;
- добавить regression-тесты и эксплуатационную документацию.

### Критерии готовности

- команда полного восстановления доступна в категории `AI: Ollama`;
- Telegram не может передать произвольную команду, путь, URL или имя модели;
- неизвестные и секретные строки `.env` сохраняются;
- дубли старых `AI_VISION_*` удаляются;
- comparison-модель очищается;
- модель без capability `vision` считается ошибкой;
- после самоперезапуска Supervisor дочерний бот получает новую конфигурацию.

### Риски и ограничения

- загрузка модели зависит от скорости сети и может превысить `SUPERVISOR_COMMAND_TIMEOUT_SECONDS`;
- для применения нового allowlist сначала требуется существующая операция самообновления Supervisor;
- после изменения `.env` нужен именно самоперезапуск Supervisor, поскольку текущий процесс уже содержит старое окружение;
- модуль не устанавливает Ollama, если `ollama.exe` отсутствует в PATH.
