## Перед началом

### Цель

Убрать из GPT Image 2 выбор 1K, 2K и 4K, поскольку provider не гарантирует
нативную детализацию этих уровней, а прежний экспорт мог только увеличить число
пикселей после генерации.

### Исходный контекст

Production-задача вернула JPEG 2160×3840 после выбора 4K, но это был размер
постобработки, а не доказательство нативного качества. Интерфейс и имя файла
создавали более сильное обещание, чем фактический provider contract.

### Планируемый объём

- убрать шаг и кнопку выбора размера из нового Telegram-flow;
- не показывать внутренний compatibility profile как качество;
- запретить апскейл исходника в JPEG exporter;
- показывать только фактические пиксели результата;
- сохранить чтение старых payload и callback-клавиатур;
- обновить тесты, документацию и package inventory.

### Вне объёма

- изменение Hermes image endpoint schema;
- обещание нативного разрешения со стороны ImageGen;
- исправление отдельного Codex rate-limit probe HTTP 502.

### Критерии готовности

- новый flow переходит от проверки данных сразу к пропорции;
- в подтверждении и прогрессе нет 1K, 2K или 4K;
- exporter никогда не создаёт пиксели сверх исходника;
- подпись результата содержит фактические width×height;
- старые задачи с полем `resolution` продолжают выполняться;
- обязательный CI зелёный.

### Риски и ограничения

Внутренний `resolution=2K` временно остаётся в bot/router payload для совместимости
с уже выпущенным Hermes runtime. Оно не влияет на размер локального JPEG export и
не выводится пользователю как гарантия качества.

## После завершения

### Фактически сделано

- экран выбора качества исключён из нового flow, stale-кнопки перенаправляются к
  выбору пропорции;
- внутренний transport profile зафиксирован и скрыт от пользовательского текста;
- JPEG exporter выполняет только центральную обрезку без апскейла и sharpening;
- прогресс показывает `JPEG · ratio`, результат показывает реальные пиксели;
- имя документа больше не содержит фиктивный уровень качества;
- добавлены regression-тесты native crop и отсутствия quality selector.

### Миграции и совместимость

Миграций базы данных нет. Поле `resolution` сохранено в DTO, результате и Hermes
протоколе, поэтому старые queued/completed задачи остаются читаемыми.

### Проверки

- focused unit-тесты GPT Image UI и export;
- package architecture inventory;
- полный protected-branch CI.

### Решения и компромиссы

Совместимое поле `resolution` не удаляется одним релизом, но перестаёт влиять на
локальный размер экспорта. Полное удаление из router schema возможно отдельной
версированной миграцией после обновления всех runtime.
