# Исправление асинхронной отправки GRS и интерфейса ожидания

## Причина

Nano Banana 2/Pro отправлялись в единый GRS API с `replyType=json`. Для тяжёлой генерации с референсами HTTP-запрос мог оставаться открытым до готового результата и превысить клиентский таймаут уже после принятия платной задачи. Экономный worker корректно запрещал слепой повтор, но показывал владельцу устаревшие Kie/createTask формулировки.

## Изменения

- GRS-запросы Nano Banana 2/Pro принудительно используют `replyType=async`.
- Сразу сохраняется GRS task id, после чего результат запрашивается через `/v1/api/result`.
- Добавлено чтение баланса GRS API key через документированный endpoint кредитов.
- Добавлен provider-aware worker интерфейса ожидания:
  - показывает GRS AI вместо Kie.ai для Banana;
  - показывает режим, качество, контент и число референсов;
  - показывает ожидаемое списание в кредитах, USD и RUB;
  - показывает текущий баланс GRS и расчётный остаток;
  - заменяет технические `worker`, `createTask` и `Kie campaign` на понятные сообщения;
  - сохраняет защиту от повторной платной отправки при неопределённом ответе.
- Подпись успешного результата теперь показывает фактического провайдера.

## Проверки

Добавлены unit-тесты для:

- `replyType=async` и возврата GRS task id;
- разбора баланса GRS;
- provider-aware текста отправки;
- понятного сообщения при неопределённом статусе первой отправки.
