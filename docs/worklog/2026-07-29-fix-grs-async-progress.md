## Перед началом

### Цель

Устранить неопределённое завершение Nano Banana Pro после отправки в GRS AI и заменить устаревшие Kie/createTask формулировки понятной карточкой ожидания с фактическим провайдером, ожидаемым списанием и текущим балансом.

### Исходный контекст

Nano Banana 2/Pro уже маршрутизировались через GRS AI, но единый endpoint вызывался с `replyType=json`. Тяжёлая 2K-генерация с двумя референсами могла держать HTTP POST открытым до готового изображения и превысить клиентский таймаут уже после принятия платной задачи. Экономный worker безопасно запрещал слепой повтор, однако сообщал владельцу о Kie.ai и `createTask`, хотя модель выполнялась в GRS.

### Планируемый объём

- перевести GRS submission на асинхронный ответ с task id;
- сохранить существующий polling `/v1/api/result`;
- добавить получение баланса GRS API key;
- показывать фактического провайдера и понятные этапы ожидания;
- показывать ожидаемое списание, текущий баланс и расчётный остаток;
- сохранить защиту от повторного платного запроса при неопределённом ответе;
- добавить тесты и документацию.

### Критерии готовности

- Nano Banana 2/Pro отправляются с `replyType=async`;
- GRS task id сохраняется до polling результата;
- в карточке ожидания Banana не упоминается как модель Kie.ai;
- карточка показывает ожидаемые кредиты, USD/RUB, баланс и остаток;
- технические `worker`, `createTask` и Kie campaign не показываются владельцу;
- существующая Kie/Seedream/video совместимость сохраняется;
- CI проходит.

### Риски и ограничения

GRS предоставляет баланс кредитов через отдельный endpoint, который может быть временно недоступен. В этом случае генерация не блокируется, а карточка сообщает, что баланс проверить не удалось. Значения 1200 и 1800 кредитов соответствуют стандартным Nano Banana 2 и Nano Banana Pro; USD/RUB остаются внутренней расчётной оценкой budget guard.

## После завершения

### Фактически сделано

- GRS submission принудительно использует `replyType=async`;
- task id сохраняется с существующим префиксом `grs:` и далее опрашивается через `/v1/api/result`;
- добавлен безопасный клиент чтения баланса GRS без вывода API key в пользовательскую ошибку;
- добавлен provider-aware worker интерфейса ожидания;
- карточка показывает модель, провайдера, режим, качество, контент, число референсов, ожидаемое списание, баланс и расчётный остаток;
- старые Kie/createTask формулировки преобразуются в понятные сообщения GRS;
- успешная доставка и терминальная ошибка показывают фактического провайдера;
- защита от автоматического оплачиваемого дубликата сохранена.

### Миграции и совместимость

Миграции PostgreSQL не требуются. Внутренний task type и economy worker остаются совместимыми с существующими заданиями. Kie продолжает использоваться только для временной загрузки Telegram-референсов, Seedream и видео. Новых переменных окружения не требуется: используются существующие `GRS_API_KEY` и `GRS_BASE_URL`.
