## Перед началом

### Цель

Устранить падение официального Hermes Agent image при интерактивной настройке и запуске gateway в server Compose.

### Исходный контекст

Официальный Hermes image `v2026.7.20` использует `s6-overlay` и `/init` как обязательный PID 1. Server Compose дополнительно задавал `init: true`, поэтому Docker вставлял `tini` перед `/init`, и Hermes завершался сообщением `s6-overlay-suexec: fatal: can only run as pid 1`.

### Планируемый объём

- не менять init-поведение Velvet bot;
- убрать Docker init только у сервиса Hermes;
- сохранить официальный Hermes entrypoint и `gateway run`;
- добавить regression-контракт на PID 1.

### Критерии готовности

- Hermes service не содержит `init: true`;
- Velvet bot сохраняет `init: true`;
- Compose сохраняет `command: ["gateway", "run"]`;
- server deployment tests проходят.

### Риски и ограничения

Hotfix не включает `HERMES_INCIDENT_ENABLED`, не выдаёт Hermes Docker socket, production `.env`, PostgreSQL volume или root-доступ. Telegram token и provider credentials остаются только в `.env.hermes` на VPS.

### Стабилизационное обоснование

Изменение исправляет несовместимость server Compose с обязательной init-моделью официального Hermes image и не добавляет новых production-разрешений.
