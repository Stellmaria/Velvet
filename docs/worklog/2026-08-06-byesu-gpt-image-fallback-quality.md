## Перед началом

### Цель

Добавить для существующего GPT Image 2 единственный платный резервный маршрут через
Byesu после чистого исчерпания лимита Codex Plus и вернуть пользователю выбор
1K, 2K или 4K как качество именно резервного маршрута.

Дополнительно зафиксировать provider-neutral контракт будущего анализатора
внешности для Nano Banana 2/Pro, Seedream 5 Pro и Wan 2.7/Pro без включения его
в этот bounded-срез.

### Исходный контекст

GPT Image 2 уже выполняет один Codex/ImageGen запуск с Sol, Terra или Luna и
выбранным reasoning effort. Автоматическая повторная генерация запрещена.
Пользовательский выбор 1K/2K/4K был удалён, потому что основной Codex/ImageGen
не подтверждает нативное качество этих уровней и прежний exporter мог лишь
увеличить число пикселей.

В Hermes уже существует Byesu provider route и отдельный
`BYESU_HERMES_CODEX_API_KEY`, но image-runner при любой ошибке первичного Codex
сразу завершает задачу. Byesu media API требует token group `media / media-gen`;
поэтому reuse существующего ключа допустим только после capability-проверки
доступности GPT-5.6 и выбранной image-модели.

### Планируемый объём

- основной маршрут остаётся `codex_subscription`;
- fallback разрешается только для `subscription_limit` до первого tool execution;
- fallback анализирует исходный промт и все референсы выбранной GPT-5.6 моделью
  Sol, Terra или Luna с выбранным reasoning effort;
- генерация выполняется ровно один раз моделью `firefly-gpt-image-2` через Byesu;
- выбранные 1K/2K/4K и пропорция передаются в Byesu как точный `size`;
- использовать существующий `BYESU_HERMES_CODEX_API_KEY`, не передавать ключ в
  Telegram-бот и не добавлять секреты в task payload;
- перед fallback проверять `/v1/models` и fail closed, если token group не видит
  анализатор или image-модель;
- не запускать fallback после tool execution, создания artifact или неизвестного
  результата генерационного запроса;
- вернуть в Telegram UI выбор качества с явной подписью, что он относится к
  резервному Byesu-маршруту;
- сохранить совместимость старых queued payload;
- добавить focused tests и эксплуатационную документацию.

### Критерии готовности

- чистая ошибка лимита до `image_gen` переключает ровно один раз на Byesu;
- `thread.started` и `turn.started` не считаются началом генерации;
- любой actual tool execution блокирует fallback;
- capability mismatch ключа завершается понятной ошибкой без генерационного
  списания;
- Byesu получает все 1–5 референсов для GPT-анализа и не более шести для
  `firefly-gpt-image-2`;
- пользователь выбирает 1K, 2K или 4K до пропорции;
- основной Codex-путь не обещает выбранное разрешение;
- task/result сохраняют requested route, actual route, fallback reason и число
  генерационных попыток;
- тесты покрывают routing guard, size mapping, UI и отсутствие второго запуска.

### Риски и ограничения

- публичная документация Byesu требует media-token; существующий Codex token
  может оказаться привязан к другой группе, что подтверждается только live smoke;
- Byesu/OpenAI-compatible multimodal Responses contract требует живой проверки
  референсов и всех reasoning effort;
- CI не может подтвердить фактическое списание, возврат или доступность модели;
- анализ Sol улучшает текстовую спецификацию, но downstream image-модель учитывает
  его только через сформированный prompt и переданные референсы;
- расширение анализатора на Banana/Seedream/Wan остаётся отдельным срезом, чтобы
  не смешивать provider fallback и изменение поведения всех фото-моделей.

### Почему это допустимо в режиме стабилизации

1. Улучшается существующая функция Ауф GPT Image 2.
2. Исчерпание лимита перестаёт превращать валидную задачу в ручной повтор.
3. Новая предметная область не добавляется: меняются provider reliability и UX.
4. Улучшение проверяется routing, one-shot, capability и UI tests.
5. Сохраняются queue, use-case, provider и Telegram delivery boundaries.
