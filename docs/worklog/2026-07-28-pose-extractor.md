## Перед началом

### Цель

Добавить в панель Qwen отдельную операцию извлечения позы из изображения и вернуть отсутствующую кнопку, которая не вошла в PR #331.

### Исходный контекст

PR #331 добавил `Фото → промт`, но намеренно исключил экспериментальный pose extractor и его незавершённую Telegram-интеграцию. В актуальном `main` не было клиента, callback, router или кнопки для этой операции.

### Планируемый объём

- отдельный vision-клиент для pose-only анализа;
- строгий контракт результата с анатомической геометрией, опорами и перекрытиями;
- последовательное сравнение `AI_VISION_MODEL` и `AI_VISION_COMPARE_MODEL`;
- Telegram ForceReply-поток и сохранение результата в AI history;
- новая кнопка в Qwen-панели;
- unit и архитектурные regression-тесты;
- документация пользовательского сценария.

### Критерии готовности

- кнопка `🧍 Поза → промт` имеет зарегистрированный callback handler;
- фотография и image-документ принимаются через ответ на ForceReply;
- результат содержит все обязательные разделы `Vᴇʟᴠᴇᴛ Pᴏsᴇ`;
- одна неудачная модель не уничтожает результат второй;
- длинный результат делится на безопасные Telegram HTML-блоки;
- новое AI-задание имеет kind `pose_extraction`;
- архитектурные списки учитывают новый controller.

### Риски и ограничения

- качество зависит от фактически доступной локальной vision-модели Ollama;
- модель может зеркалить лево и право или додумывать скрытые суставы, поэтому инструкция требует повторной проверки и строгой валидации разделов;
- live-проверка на целевой Windows с реальными моделями остаётся обязательной;
- ветка не исправляет отдельно существующую конфигурацию каталога Ollama и ошибки загрузки моделей.

## После завершения

### Фактически сделано

- добавлен `PoseExtractorClient` поверх существующего локального image-to-prompt transport;
- введён формат `Vᴇʟᴠᴇᴛ Pᴏsᴇ` с разделами для количества персонажей, общей схемы, головы, корпуса, рук, ног, опор, контактов, ракурса, готового pose prompt и negative prompts;
- добавлена повторная компактная попытка, выбор более полного результата и проверка порядка обязательных разделов;
- добавлен Telegram-controller `velvet_ai_pose.py`;
- сохранены последовательный запуск моделей, общая AI-блокировка, частичный успех и текстовая доставка в чат;
- добавлена кнопка `🧍 Поза → промт` в основную Qwen-панель;
- router подключён через canonical quality bundle;
- добавлены unit-тесты pose-контракта, меню и архитектурного состава;
- добавлена отдельная документация `docs/POSE_EXTRACTION.md`, чтобы не конфликтовать с Ollama-hotfix в общем `AI_VISION.md`.

### Миграции и совместимость

Миграции базы данных не требуются. Используется существующая таблица AI jobs и новый строковый kind `pose_extraction`. Настройки `.env` не расширяются: операция использует текущие `AI_VISION_*` параметры и наследует проверку capability `vision` из hotfix #333 после синхронизации с `main`.

### Проверки

- новые Python-файлы и тест pose extractor прошли локальную синтаксическую проверку `py_compile`;
- выполнена source-level проверка callback, AI job kind, текстовой доставки и архитектурного router inventory;
- полный test suite, type check, project notes contract и Docker build выполняются GitHub CI;
- живая Ollama-проверка на Windows не выполнена в этой сессии.
