## Перед началом

### Цель

Устранить повторный `TelegramBadRequest: MESSAGE_TOO_LONG` при открытии истории безопасной консоли и сократить обычное меню до команд, которые действительно нужны при повседневной эксплуатации Supervisor.

### Исходный контекст

После исправления длинного вывода отдельной операции сама история продолжала собирать до пятнадцати записей вместе с фрагментами stdout и error. Несколько результатов Ollama и полного набора тестов легко превышали лимит Telegram. Одновременно каталог показывал все allowlist-команды, включая устаревшие Ollama-действия, аварийные stash/clean-команды и системную диагностику, дублирующую штатные экраны Supervisor.

### Планируемый объём

- ограничить размер истории операций до безопасного бюджета Telegram;
- не включать stdout успешных операций в историю;
- оставить короткую диагностику только для ошибочных операций;
- сохранить полный вывод в карточке операции и существующем `.txt`-вложении;
- отделить основной пользовательский набор команд от полного безопасного allowlist;
- скрыть из обычного меню дублирующие, устаревшие и аварийные команды;
- сохранить возможность точного вызова скрытых команд;
- добавить регрессионные тесты.

### Критерии готовности

- история из двадцати намеренно огромных операций укладывается в 3600 символов;
- успешные stdout не копируются в историю;
- ошибки сохраняют короткий хвост output/error;
- основные команды остаются видимыми и доступны кнопками;
- аварийные и legacy-команды исчезают из обычного списка, но продолжают разрешаться реестром;
- shell-синтаксис и произвольные команды по-прежнему запрещены;
- полный CI проходит.

### Риски и ограничения

- история становится обзорной, а не полноценным архивом stdout;
- для полного результата необходимо открыть карточку операции или приложенный текстовый файл;
- скрытые команды требуют точного ввода ключа или alias;
- общий `_safe_edit` остаётся последней границей Telegram API, поэтому каждый генератор интерфейса всё равно должен иметь собственный разумный лимит.
