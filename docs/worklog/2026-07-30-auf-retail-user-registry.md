## Перед началом

### Цель

Разделить реальную себестоимость и пользовательскую цену генераций, скрыть внутренние финансовые данные от обычного пользователя, закрыть системные референсы, добавить уведомления о пополнении, команды начисления и структурный реестр пользователей.

### Исходный контекст

Пользовательский кошелёк показывал внутреннее покрытие API и USD-цены. Розничная цена генерации напрямую вычислялась из себестоимости. Обычный пользователь мог видеть системное пространство в выборе референсов. Заявка на пополнение не создавала отдельного уведомления владельцу, а начисление по Telegram ID или username отсутствовало. Единого реестра первого и последнего входа и обезличенной истории действий не было.

### Планируемый объём

- отдельные розничные тарифы моделей и пакетов;
- скрытие себестоимости и внутренних курсов в обычном интерфейсе;
- исключение системной базы референсов для обычных пользователей;
- уведомление владельца о каждой заявке на пополнение;
- команды `/velvet_grant`, `/velvet_user`, `/velvet_users`;
- таблицы `telegram_users` и `telegram_user_events`;
- middleware без хранения текста сообщений, промтов и файлов.

### Критерии готовности

- пользователь видит только цену в вельветах и рублях;
- списание использует утверждённую розничную сетку, а системная аналитика сохраняет себестоимость;
- системные референсы доступны только глобальному владельцу;
- заявка на пополнение немедленно приходит владельцу с кнопкой подтверждения;
- начисление работает по ID и известному username;
- карточка пользователя показывает входы, активность, генерации, баланс и оплаты;
- миграции, тесты, type check, Docker build и project notes contract проходят.

### Риски и ограничения

Username можно разрешить только после хотя бы одного взаимодействия пользователя с ботом. Реестр намеренно не сохраняет текст сообщений, промты, содержимое файлов и значения callback-параметров. Старые завершённые генерации не пересчитываются по новым тарифам.
