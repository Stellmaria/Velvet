## Перед началом

### Цель

Убрать необходимость вручную проверять USD/RUB для себестоимости Kie и добавить одну официальную проверку курса в сутки через API Национального банка Республики Беларусь.

### Исходный контекст

После PR #368 стоимость фактически списанных кредитов считалась корректно от `creditsConsumed`, но пересчёт долларов в российские рубли продолжал использовать ручной `KIE_USD_TO_RUB`. Это безопасный fallback, однако курс мог устаревать между ручными обновлениями.

### Планируемый объём

- получать USD и RUB из официального API НБРБ;
- учитывать `Cur_Scale`, поскольку курс RUB публикуется за 100 единиц;
- вычислять официальный кросс-курс USD/RUB через BYN;
- выполнять не более одной внешней попытки за календарный день Минска;
- хранить результат и дату в PostgreSQL;
- восстанавливать последний успешный курс после перезапуска;
- применять курс к бюджетной оценке Kie и экрану баланса;
- сохранять ручной `KIE_USD_TO_RUB` как fallback.

### Критерии готовности

- один успешный или неуспешный запрос к НБРБ фиксируется один раз за день;
- USD и RUB принимаются только за одинаковую дату эффективности;
- расчёт учитывает масштаб каждой валюты;
- генерации продолжают работать при недоступности НБРБ;
- экран баланса показывает использованный официальный курс и дату;
- после рестарта используется последний сохранённый курс.

### Риски и ограничения

- официальный кросс-курс может отличаться от коммерческого курса банка или обменника;
- при единственной неуспешной попытке новая проверка произойдёт на следующий день;
- runtime-интеграция использует существующий worker registry без изменения пользовательских маршрутов;
- миграция добавляет только отдельную таблицу истории ежедневных проверок.
