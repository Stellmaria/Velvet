## Перед началом

### Цель

Перевести фото-контур Ауф на выбор модели до сбора исходных данных, починить
потерю уже отправленных референсов у Qwen Image 2.0 и FLUX.2 Pro, открыть
text-to-image режимы и добавить только подтверждённые настройки конкретных
моделей.

### Исходный контекст

Существующий FSM сначала требовал одновременно фото и текст, а модель выбиралась
после проверки исходных данных. Каждый запрос затем принудительно создавался как
`PHOTO_TEXT`. Из-за наложения нового фото-роутера, legacy-состояний и поздних
installer wrappers Qwen и FLUX повторно запрашивали референс, хотя фото уже было
принято. Seedream имел backend text route, но UI до него не доходил.

Nano Banana Pro был закреплён за GRS, но использовал обычный route. Для текущей
схемы требуется сначала использовать `nano-banana-pro-vt`, а после явного
terminal failure последовательно переключаться на обычный
`nano-banana-pro`, не создавая fallback при timeout или неизвестном результате.

### Планируемый объём

- выбирать модель до режима и исходных данных;
- поддержать только `Только текст` и `Фото + текст`;
- не добавлять photo-only/variation режим;
- показывать лимиты модели и размер одного файла до 10 МБ;
- принимать промт одним или двумя Telegram-сообщениями без обрезания;
- сохранить референсы и текст при переходе между настройками;
- добавить text routes Qwen2 и FLUX.2, text payload для Wan;
- разрешить PNG/JPEG только для Seedream;
- добавить Wan `n` и `enable_sequential` с пропорциональной ценой;
- не добавлять seed, thinking mode, watermark, bbox, callback и content profile;
- скрыть названия провайдеров на пользовательских экранах;
- использовать Banana Pro VT с безопасным fallback на обычный Pro;
- не изменять видеоконтур.

### Критерии готовности

- Qwen, FLUX и Wan не теряют уже принятые референсы;
- text-only запросы не содержат фиктивные image fields;
- каждая модель применяет собственный лимит референсов и промта;
- третий текстовый фрагмент и лишний референс отклоняются до API;
- Seedream передаёт выбранный PNG или JPEG;
- Wan передаёт только `n` и `enable_sequential` из расширенных настроек;
- цена Wan умножается на число результатов;
- Banana Pro сначала отправляется в VT route и переключается на обычный route
  только после явного failed status;
- финальный экран не показывает provider, seed и content profile;
- unit tests, type check, project notes contract и docker build проходят.

### Риски и ограничения

- live smoke-тесты требуют реальных ключей и расходуют баланс;
- публичная документация Wan описывает поля `n` и `enable_sequential`, но
  поведение связной серии дополнительно подтверждается внешними API-обёртками;
- fallback Banana не запускается при timeout, сетевом разрыве или неизвестном
  статусе, чтобы исключить возможное двойное списание;
- текущая реализация сохраняет installer-композицию проекта и не удаляет legacy
  photo router в этой задаче.

### Миграции и совместимость

Миграции PostgreSQL не требуются. Существующие queued payload остаются
совместимыми: новые поля Wan находятся в `extra_input`, а старые задачи без них
используют `n=1` и выключенный sequential. Legacy photo router остаётся в коде,
но production composition заменяет его model-first controller перед регистрацией
Telegram handlers.
