## Перед началом

### Цель

Прекратить бесконечное увеличение инцидента #104 для отсутствующего исторического Windows-пути, не ослабляя запрет удаления файлов вне текущего Krita bridge.

### Исходный контекст

Telegram Storage создавал `KritaBridge` повторным чтением `KRITA_BRIDGE_DIR`, а не из уже проверенного `TelegramStorageSettings`. После переноса с Windows в базе остались пути вида `E:\VelvetKritaBridge\sources\...`. На Linux такой файл отсутствует, но каждая фоновая очистка снова записывала WARNING `Refusing to delete path outside Krita bridge`.

### Планируемый объём

- использовать канонический `settings.krita_bridge_dir`;
- понизить отсутствующие исторические внешние пути до DEBUG;
- сохранить WARNING и отказ для реально существующих внешних путей;
- закрепить поведение регрессионными тестами;
- не менять allowlist и deletion policy.

### Критерии готовности

- старый отсутствующий путь исключается из очистки без WARNING;
- существующий внешний файл исключается из очистки с WARNING;
- файл внутри настроенного bridge принимается;
- изменение environment после создания settings не меняет корень bridge;
- deletion policy и архитектурные проверки проходят.

### Риски и ограничения

Нельзя просто убрать предупреждение для всех внешних путей: это скрыло бы реальную ошибку конфигурации или попытку удалить существующий файл вне bridge. Разделение уровней выполняется только по фактическому существованию пути или ссылки.

## После завершения

### Фактически сделано

- `TelegramStorageMigrationService` теперь создаёт `KritaBridge` из `self.settings.krita_bridge_dir`;
- отсутствующий внешний путь остаётся отклонённым и записывается на DEBUG;
- существующий внешний путь или symlink остаётся отклонённым и записывается на WARNING;
- добавлены тесты на drift env/settings, исторический отсутствующий путь, существующий внешний путь и допустимый путь внутри bridge.

### Миграции и совместимость

SQL-миграции не требуются. Старые значения путей в PostgreSQL можно оставить: после обновления они безопасно игнорируются и больше не создают предупреждение. Allowlist и правила удаления не расширены.

### Проверки

Целевые регрессии Krita cleanup, deletion policy, deletion preflight и package architecture inventory завершились успешно. Полный CI запускается на финальном head PR.
