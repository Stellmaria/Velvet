## Перед началом

### Цель

Расширить безопасное восстановление Ollama через Supervisor так, чтобы оно находило перенесённые модели на диске `E:`, устанавливало недостающий фиксированный набор VLM/LLM, обновляло `.env` и не требовало PowerShell.

### Исходный контекст

После переноса Ollama в `E:\OllamaModels` API возвращал пустой список моделей, хотя в каталоге сохранялись `blobs` и `manifests`. Старый recovery был жёстко привязан к `qwen3-vl:4b`, очищал comparison-модель и не поддерживал текстовую reasoning-модель.

### Планируемый объём

- заменить одну жёстко заданную модель фиксированным набором ролей;
- научить recovery восстанавливать имена моделей из путей manifests;
- переиспользовать существующие blobs через повторный `ollama pull`;
- атомарно обновлять только разрешённые AI/Ollama-переменные;
- сохранить старые внутренние allowlist-ключи для совместимости;
- переименовать видимые кнопки безопасной консоли;
- добавить тесты и эксплуатационную документацию.

### Критерии готовности

- Supervisor видит `E:\OllamaModels` и `E:\OllamaModels\models`;
- уже зарегистрированные модели не скачиваются повторно;
- модели из manifests повторно регистрируются без удаления blobs;
- отсутствующие модели ставятся последовательно;
- три VLM проверяются по capability `vision`, LLM по `completion`;
- `.env` содержит primary, compare, fallback и text-роли;
- старые argv-команды остаются фиксированными и shell-free;
- тесты покрывают конфигурацию, manifests, выборочную установку и кнопки.

### Риски и ограничения

- суммарная загрузка нескольких моделей может превысить стандартный таймаут Supervisor;
- 8B/9B модели на RTX 3050 Ti 4 ГБ будут частично использовать RAM и работать медленно;
- `AI_TEXT_MODEL` и `AI_VISION_FALLBACK_MODEL` подготавливаются конфигурацией, но их автоматическое применение в отдельных бизнес-сценариях требует соответствующего клиента;
- доступность конкретного Hugging Face GGUF зависит от внешнего репозитория модели и сети.
