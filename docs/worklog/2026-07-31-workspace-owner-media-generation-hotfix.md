## Перед началом

### Цель

Разрешить владельцам собственных пространств обычное использование полученных в личном чате файлов, убрать двадцатисекундную задержку после подтверждённого отказа генератора, вернуть видимый счётчик попыток и восстановить запуск Qwen Image 2.0, Wan 2.7 Image и FLUX.2 Pro.

### Исходный контекст

Центральный `ProtectedMediaBot` снимал защиту только для глобальных владельцев из конфигурации. Worker формировал строку попытки, но финальный privacy-слой удалял её. Model-first фото-поток был обёрнут несколькими сохранёнными обработчиками, поэтому новые `photo_*` callback могли попадать в устаревший маршрут.

### Планируемый объём

- проверять роль владельца пространства перед отправкой защищаемого медиа в личный чат;
- ускорять только подтверждённые terminal failure провайдера, не меняя backoff сетевых ошибок;
- вернуть пользователю счётчик попыток без раскрытия провайдера, task ID и служебной экономики;
- свести `create` и `photo_*` callback к одному актуальному model-first маршруту;
- добавить регрессии для Qwen, Wan, FLUX, прав владельца и retry-политики.

### Критерии готовности

- владелец хотя бы одного пространства получает личное медиа без `protect_content`;
- пользователь с иной ролью продолжает получать защищённое медиа;
- после `KieTaskFailed` следующая последовательная попытка запускается без паузы;
- сетевые и неопределённые ошибки сохраняют прежний backoff;
- прогресс содержит `Текущая попытка: N/50` и не содержит служебных деталей;
- Qwen Image 2.0, Wan 2.7 Image и FLUX.2 Pro проходят актуальный callback-маршрут до постановки задачи;
- полный CI проходит.

### Риски и ограничения

- ошибочно снять защиту у участника без роли владельца;
- повторять сетевую ошибку без паузы и создать платный дубликат;
- сломать старые Banana и Seedream маршруты при исправлении Qwen, Wan и FLUX;
- раскрыть пользователю provider, task ID или служебную экономику вместе со счётчиком попытки;
- Telegram-клиент определяет фактическое поведение скриншотов, бот управляет только `protect_content`.

### Стабилизационное обоснование

Изменение устраняет расхождение между ролью владельца пространства и глобальной защитой медиа, а также сводит разросшиеся runtime-обёртки фото-интерфейса к одному финальному маршруту. Новых предметных сущностей и публичных API не добавляется.

## После завершения

Статус: завершено.

### Фактически сделано

- роль владельца проверяется через workspace repository непосредственно перед отправкой защищаемого медиа в личный чат;
- только роль `owner` получает снятие `protect_content`; остальные роли сохраняют защиту;
- любой подтверждённый `KieTaskFailed` получает нулевую очередь ожидания, но сетевые и неопределённые ошибки сохраняют backoff;
- публичный прогресс сохраняет строку `Текущая попытка: N/50`, продолжая скрывать provider, task ID и реальные расходы;
- после установки всех UI-слоёв регистрируется один канонический обработчик `create` и `photo_*`;
- Qwen, Wan и FLUX направляются в актуальный model-first handler, а финальные ratio, format, Wan и generate действия используют текущие wallet и pricing функции;
- добавлены регрессии на права владельца, мгновенный повтор, счётчик и маршрутизацию трёх моделей;
- ветка синхронизирована с актуальным `main`, generated-инвентари и контрактные ожидания пересобраны штатными скриптами.
