# Сессия: восстановление меню Ауф, служебные балансы и SIGTERM

## Перед началом

### Цель

Восстановить обработку кнопок корневого меню Ауф, добавить Стэл единый закрытый экран внешних и внутренних балансов и убрать штатный SIGTERM из непросмотренных ошибок.

### Исходный контекст

В рабочем меню Ауф кнопки перестали переходить к генерации и связанным экранам. Корневой экран не показывал provider-specific балансы даже глобальному владельцу, для Byesu интеграции баланса не существовало, а `Received SIGTERM signal` при обновлении Supervisor сохранялся как предупреждение error center.

Финальный owner hotfix устанавливал общий callback-обработчик Ауф через `*args` и `**kwargs`. Эта граница охватывала фото, кошелёк, runtime и fallback-действия, поэтому критическая цепочка зависела от неявного контракта внедрения зависимостей aiogram.

### Планируемый объём

- заменить variadic callback-wrapper явной сигнатурой runtime-зависимостей;
- добавить служебный owner-only экран Kie.ai, GRS AI, Byesu и внутреннего кошелька Velvet;
- выполнять внешние проверки параллельно и с ограничением времени;
- не показывать ключи, provider payload и технические ответы пользователям;
- исключить ожидаемые SIGTERM/SIGINT из новых инцидентов и автоматически закрыть старые;
- добавить контрактные тесты маршрутизации, приватности и runtime-фильтрации.

### Критерии готовности

- кнопки Ауф регистрируются через обработчик с явным DI-контрактом;
- служебная кнопка видна только глобальному владельцу;
- Стэл получает на одном экране три внешних баланса и внутренний кошелёк;
- отсутствие или недоступность одного провайдера не ломает весь экран;
- штатные SIGTERM/SIGINT не создают owner-actionable incident;
- старый непросмотренный SIGTERM закрывается startup-cleanup;
- type check, tests, docker build и project notes contract проходят в PR.

### Риски и ограничения

Фактические значения внешних балансов зависят от настроенных production-ключей и доступности API провайдеров. Живая Telegram-проверка и обновление сервера выполняются после слияния и запуска новой версии Supervisor. Изменения не должны раскрывать служебные сведения обычным владельцам пространств.

## После завершения

### Фактически сделано

- callback-wrapper canonical photo route получил явную сигнатуру всех сервисов и явную передачу аргументов в fallback-цепочку;
- в корень Ауф добавлена кнопка `📊 Балансы API · Стэл`, доступная только глобальному владельцу;
- служебный callback зарегистрирован раньше общего Auf handler;
- новый экран параллельно читает Kie.ai, GRS AI и Byesu, затем показывает внутренний кошелёк Velvet: доступно, в резерве и потрачено за 30 дней;
- внешние запросы ограничены по времени, ошибки одного источника изолированы;
- ключи и необработанные ответы не выводятся в Telegram;
- `Received SIGTERM signal` и `Received SIGINT signal` классифицированы как ожидаемое завершение aiogram;
- startup-cleanup расширен для автоматического подтверждения старых SIGTERM/SIGINT incidents.

### Миграции и совместимость

Миграции базы данных не требуются. Формат существующих callback-data сохранён. Обычные пользователи продолжают видеть только пользовательский кошелёк и генерационные действия; служебный экран защищён отдельной проверкой global owner даже при ручной подстановке callback-data.

Для Byesu используется отдельная переменная окружения `BYESU_API_KEY` либо уже настроенный AI-ключ, если соответствующий base URL указывает на Byesu. Без подходящего ключа экран остаётся рабочим и показывает нейтральный статус недоступности.
