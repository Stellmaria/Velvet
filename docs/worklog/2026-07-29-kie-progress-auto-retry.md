## Перед началом

### Цель

Добавить владельцу видимый процентный прогресс генерации Kie, сделать автоматические повторы ошибок понятными в Telegram и завершить корректную маршрутизацию Seedream 5 Pro между text-to-image и image-to-image endpoint.

### Исходный контекст

После слияния PR #355 бот умеет принимать текст и до пяти Telegram или библиотечных референсов, ставить `media.generate.kie` в общую PostgreSQL-очередь и выполнять задачу через Kie. Очередь уже поддерживает retry по `max_attempts`, но владелец не видел ни текущий этап, ни информацию о повторном запуске. Seedream также использовал один model id для текстового и референсного режима, хотя Kie публикует разные endpoint.

### Планируемый объём

- показывать отдельное Telegram-сообщение с полосой и процентом выполнения;
- обновлять прогресс на этапах claim, подготовки референсов, загрузки, отправки provider request, ожидания, успеха и ошибки;
- отображать номер текущей попытки и максимальное число попыток;
- при ошибке явно показывать автоматическую повторную постановку и задержку;
- сократить retry delay генераций до 5–30 секунд;
- не повторять платный provider call из-за ошибки доставки результата в Telegram;
- добавить callback обновлений в Kie polling client;
- разделить Seedream text-to-image и image-to-image model id;
- сохранить поддержку старого `KIE_SEEDREAM_5_PRO_MODEL` как image fallback;
- обновить env-контракт и unit-тесты.

### Критерии готовности

- прогресс отображается в виде полосы и числа от 0 до 100 процентов;
- процент никогда не выходит за диапазон 0–100;
- reference upload отражается отдельными этапами;
- polling provider обновляет этап генерации;
- успешная задача достигает 100 процентов до отправки результата;
- ошибка, допускающая retry, показывает номер следующей попытки и задержку;
- queue lifecycle остаётся единственным механизмом повторов;
- terminal failure уведомляется только после исчерпания попыток;
- Seedream text request использует `seedream/5-pro-text-to-image` без `image_urls`;
- Seedream reference request использует `seedream/5-pro-image-to-image` с `image_urls`;
- тесты, mypy, Docker build и project notes contract проходят.

### Риски и ограничения

- Kie не сообщает точный вычислительный процент, поэтому шкала является этапной оценкой, а не телеметрией GPU;
- каждый повтор provider generation может быть отдельной платной попыткой, если предыдущая задача была принята и тарифицирована провайдером;
- максимальное число попыток определяется queue task, сейчас интерфейс создаёт до трёх попыток суммарно;
- progress message создаётся отдельно для каждой queue-попытки, поскольку message id пока не сохраняется в task payload;
- live Kie calls в CI запрещены.

## После завершения

### Фактически сделано

- добавлена текстовая прогресс-полоса из десяти сегментов;
- worker публикует этапы от 0 до 100 процентов;
- progress message обновляется через `edit_message_text`;
- добавлены этапы загрузки каждого референса;
- Kie polling вызывает асинхронный callback после каждого полученного состояния;
- состояния waiting, queuing, generating, success и fail преобразуются в этапный процент;
- retry queue показывается владельцу вместе с номером попытки и задержкой;
- retry delay Kie-задач ограничен диапазоном 5–30 секунд;
- успешная queue task завершается до best-effort Telegram delivery, поэтому ошибка отправки результата не вызывает новый provider call;
- `KieModelCatalog` разделяет Seedream text и image endpoint;
- Seedream text payload не содержит `image_urls`;
- Seedream image payload содержит `image_urls`, `output_format` и mature-флаг;
- добавлены новые env-переменные и сохранён legacy fallback;
- расширены unit-тесты provider routing, progress callback, полосы прогресса и retry notification.

### Миграции и совместимость

Миграции базы данных не требуются. Используется существующий `attempt_count`, `max_attempts`, `not_before` и error lifecycle таблицы `ai_tasks`. Старый `KIE_SEEDREAM_5_PRO_MODEL` продолжает работать как fallback для image-to-image, но новые окружения должны использовать два явных параметра.
