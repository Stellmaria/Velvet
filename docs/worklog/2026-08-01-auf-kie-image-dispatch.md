- ID: `auf-kie-image-dispatch`
- Линия/фаза: `production hotfix`
- Статус: `завершено`

- Базовый commit: `ffa6f5272d321fdcc9864f9172819c357a674f48`

## Перед началом

### Цель

Восстановить запуск пользовательских генераций Qwen Image 2.0, Wan 2.7 Image и FLUX.2 Pro после подтверждения цены.

### Исходный контекст

Пользовательская кнопка подтверждения успешно создавала `ai_tasks` запись и атомарно резервировала один вельвет, после чего задача оставалась в очереди без сообщения о прогрессе. Общий Kie dispatcher выбирает задачи по `AufProvider.KIE.model_aliases`, но в этом allowlist отсутствовали алиасы трёх новых image-моделей:

- `qwen2_image_edit`;
- `wan_27_image`;
- `flux_2_pro_image`.

Из-за этого ни один Kie worker не мог claim-ить уже оплаченную queued-задачу.

### Планируемый объём

- добавить три существующих Kie image alias в канонический provider route;
- проверить полное покрытие каталога ровно одним provider route;
- не менять цены, резервирование, provider payload, схему базы и callback-контракт.

### Критерии готовности

- Qwen, Wan Image и FLUX задачи входят в Kie dispatcher allowlist;
- весь `KieModelAlias` каталог покрыт объединением Kie и GRS маршрутов;
- Kie и GRS маршруты остаются непересекающимися;
- уже созданные queued-задачи начинают обрабатываться после deployment без повторного резервирования.

## После завершения

### Фактически сделано

- `qwen2_image_edit`, `wan_27_image` и `flux_2_pro_image` добавлены в `AufProvider.KIE.model_aliases`;
- добавлена регрессия на три production-модели;
- добавлен общий контракт, запрещающий появление моделей каталога без provider route или одновременно в двух маршрутах.

### Экономика и совместимость

Миграции отсутствуют. Существующие queued-задачи и `auf_task_charges` не изменяются. После перезапуска dispatcher сможет claim-ить ранее созданные задачи; новое списание или новый enqueue для этого не требуются.

### Проверки

Полный GitHub Actions CI запускается на отдельном pull request от актуального `main`.

### Незавершённое

После deployment требуется проверить, что ранее зависшие Qwen/Wan/FLUX задачи переходят из `queued` в `running`, появляется Telegram progress и резерв завершается capture либо refund по фактическому результату.
