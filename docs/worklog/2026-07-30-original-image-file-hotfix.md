## Перед началом

### Цель

Гарантировать, что каждое успешно сгенерированное изображение сначала отправляется пользователю как исходный файл-документ без сжатия Telegram, а затем как удобный предпросмотр.

### Исходный контекст

Текущий image flow отправлял `send_photo` раньше `send_document`. Если предпросмотр проходил, а последующая отправка документа завершалась ошибкой, пользователь видел только сжатую картинку. Ошибка оригинального файла перехватывалась внешним best-effort обработчиком и оставалась только в логах без понятного сообщения пользователю.

### Планируемый объём

- отправлять исходный файл через `send_document` раньше предпросмотра;
- включить `disable_content_type_detection=True` для принудительной файловой доставки;
- независимо обрабатывать ошибку документа и ошибку предпросмотра;
- уведомлять пользователя о частичной доставке без повторного запуска платной генерации;
- применить исправление к базовому и provider-aware worker;
- добавить unit-тесты порядка и fallback-сценариев.

### Критерии готовности

- оригинальный файл отправляется раньше `send_photo`;
- документ содержит исходные байты и исходное имя файла;
- ошибка документа не блокирует предпросмотр;
- ошибка предпросмотра не отменяет уже отправленный оригинал;
- пользователь получает предупреждение о неполной доставке;
- повторная платная генерация не запускается.

### Риски и ограничения

- Telegram может отклонить отдельный файл из-за собственного лимита или временной сетевой ошибки;
- результат по-прежнему загружается в память перед отправкой;
- исправление не восстанавливает автоматически оригиналы старых завершённых генераций;
- качество исходного файла определяется провайдером и не меняется ботом.

## После завершения

### Фактически сделано

- добавлен runtime hotfix `original_image_delivery_hotfix`;
- `send_document` выполняется первым с `disable_content_type_detection=True`;
- `send_photo` выполняется отдельной независимой операцией после оригинала;
- для документа создаётся новый `BufferedInputFile` из исходных provider bytes;
- ошибки обеих отправок изолированы и записываются в лог;
- при частичной доставке бот сообщает, что именно не отправилось;
- исправление установлено для `FileDeliveryKieGenerationWorker` и `FriendlyKieGenerationWorker`;
- добавлены тесты успешного порядка, ошибки документа и ошибки предпросмотра.

### Миграции и совместимость

Миграции базы и новые переменные окружения не требуются. Provider API, очередь, стоимость и списания не меняются. Исправление касается только Telegram-доставки уже готового результата.
