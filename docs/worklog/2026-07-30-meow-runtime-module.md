## Перед началом

### Цель

Заменить фиксированное число media-worker-слотов динамическим диспетчером Kie/GRS, подключить Мяу как штатный модуль личного пространства и добавить управление параллельностью и отменой задач без внедрения пользовательских Ауф-токенов.

### Исходный контекст

До этой работы число media-worker-слотов задавалось статической переменной окружения с пределом восемь. Мяу показывался владельцам пространств отдельной кнопкой, но серверные обработчики разрешали его только глобальному владельцу. Общий AI-бюджет и durable-очередь уже существовали, однако отдельных provider-пулов, квоты пространства, runtime-настроек и пользовательской остановки media-задач не было.

### Зафиксированные правила

- глобальные пределы Стэл: Kie до 100 и GRS до 100;
- владелец личного пространства задаёт предел от 1 до 20, стартовое значение 5;
- задачи Стэл получают следующий свободный слот раньше пользовательских, но активные генерации не прерываются;
- Kie ограничивается скоростью не более 20 новых provider-задач за 10 секунд;
- Стэл разрешает модуль пространству, владелец включает его и может скрыть кнопку только у себя;
- до отправки провайдеру задача отменяется полностью;
- после отправки оплаченная попытка продолжает отслеживаться и успешный результат всё равно доставляется;
- после ошибки отменённой оплаченной попытки новая платная попытка не запускается;
- история задач и кошельки Ауф-токенов в этот этап не входят.

### Планируемый объём

- PostgreSQL-настройки runtime и пространства;
- модуль `meow` в продуктовой политике;
- персональная настройка отображения модуля;
- один долгоживущий динамический dispatcher вместо фиксированного количества polling-worker-ов;
- независимые provider-пулы Kie и GRS;
- приоритет Стэл и квота пространства;
- Telegram-управление лимитами;
- однократное уведомление о первичной настройке;
- кнопки отмены в очереди и progress-сообщении;
- регрессионные тесты и полная проверка CI.

### Критерии готовности

- Kie и GRS используют независимые runtime-пределы до ста задач;
- личное пространство не выполняет больше настроенного количества задач одновременно;
- Стэл получает следующий доступный слот раньше владельцев пространств;
- модуль недоступен до разрешения Стэл и включения владельцем;
- персональное скрытие кнопки не выключает модуль для пространства;
- ожидающая задача отменяется без provider-вызова;
- уже созданная provider-задача продолжает отслеживаться и доставляется при успехе;
- после terminal failure отменённой попытки новый платный запуск не создаётся;
- CI проходит.

### Риски и ограничения

- публичный GRS API не сообщает числовой предел аккаунта, поэтому значение 100 остаётся управляемой настройкой владельца;
- отмена уже созданной provider-задачи не гарантирует остановку вычислений на стороне провайдера;
- динамический dispatcher должен учитывать durable-статусы PostgreSQL после перезапуска;
- модульная политика не должна расширять глобальный `AccessPolicy` владельцам личных пространств;
- миграция обязана расширить SQL CHECK старого списка модулей;
- production smoke-test возможен только после слияния и обновления серверного checkout.
