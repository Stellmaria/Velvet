## Перед началом

### Цель

Устранить ложное падение операции Supervisor `update` на Windows в проверке синтаксиса серверных shell-скриптов.

### Исходный контекст

Полный локальный прогон завершался двумя одинаковыми сбоями `test_shell_scripts_parse_with_bash` для `deploy/server/deploy.sh` и `deploy/server/verify-dump.sh`. Оба процесса возвращали код 1 без сообщения в stderr. Тест считал любой найденный через `shutil.which("bash")` исполняемый файл рабочим Bash и передавал ему Windows-путь к скрипту.

### Планируемый объём

Изменить только `tests/test_server_deployment_contract.py`: проверить работоспособность найденного Bash, исключить прямую передачу Windows-путей и улучшить диагностическое сообщение. Production-скрипты и код Supervisor не менять.

### Критерии готовности

- неработающий WSL launcher не вызывает ложное падение тестового набора;
- рабочий Bash продолжает проверять синтаксис обоих deployment-скриптов;
- настоящая ошибка показывает доступный stdout или stderr;
- полный GitHub Actions test workflow и type check проходят.

### Риски и ограничения

Windows может находить разные реализации `bash.exe`, включая Git Bash и WSL launcher. Проверка не должна скрывать синтаксические ошибки на Linux CI, но обязана корректно пропускаться, когда найденный launcher фактически не запускается.

## После завершения

### Фактически сделано

Добавлена предварительная команда `bash --version`. Неработающий launcher теперь приводит к `skipTest` с диагностикой. Текст каждого shell-скрипта передаётся в `bash -n` через stdin, поэтому проверка не зависит от преобразования путей `E:\\...`. Сообщение assertion теперь объединяет stderr и stdout и содержит код возврата при пустом выводе.

### Миграции и совместимость

Миграции базы данных и конфигурации не требуются. Production shell-скрипты, Supervisor и серверный Compose не изменены. Поведение Linux CI сохраняется.
