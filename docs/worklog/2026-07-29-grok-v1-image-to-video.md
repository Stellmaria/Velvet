## Перед началом

### Цель

Сделать рабочим раздел `Мяу → Оживить` на старой модели Kie.ai `grok-imagine/image-to-video`: одно внешнее фото и текстовое описание движения должны превращаться в короткое видео с удобной настройкой, контролем стоимости и надёжной доставкой в Telegram.

### Исходный контекст

Кнопка `Оживить` уже присутствовала в корневом меню, но возвращала заглушку. В доменной модели был зарезервирован alias `GROK_IMAGINE_VIDEO` со старым text-to-video model id, а worker передавал видео в Telegram внешним URL. Предыдущая живая генерация изображения показала, что Telegram может отказаться скачивать временный provider URL, поэтому видеодоставка должна сначала получать оригинальные байты на стороне бота.

### Планируемый объём

- отдельный FSM-поток image-to-video;
- выбор одного референса из базы или Telegram;
- обязательный текст движения;
- настройки качества, длительности, формата и режима;
- экран проверки стоимости и бюджетный guard;
- защита от двойного платного запуска;
- provider payload старого Grok Imagine v1;
- скачивание готового MP4 и загрузка в Telegram;
- конфигурация и совместимость со старым env;
- unit-тесты UI, payload, pricing, config и delivery.

### Критерии готовности

- `Мяу → Оживить` проходит путь фото → текст → параметры → подтверждение → очередь;
- provider получает `grok-imagine/image-to-video`, одно изображение и документированные параметры;
- Spicy не предлагается для внешнего изображения;
- стоимость показывается до запуска и проверяется общим AI budget;
- повторное нажатие одной формы не создаёт вторую задачу;
- готовый MP4 отправляется байтами, а при невозможности video preview приходит оригинальным документом;
- full tests, type check, Docker build и project notes contract завершаются успешно.

### Риски и ограничения

- старый Grok v1 принимает ровно одно внешнее изображение;
- provider URL результата может истечь, поэтому его нужно скачать сразу;
- Telegram ограничивает размер Bot API upload, в этой фазе установлен предел 50 МБ;
- режим Spicy несовместим с external image input и исключён из интерфейса;
- фактическая доступность модели и тариф остаются внешней зависимостью Kie.ai;
- живая платная проверка выполняется только после слияния и обновления локального бота.

## После завершения

### Фактически сделано

- добавлен отдельный `MeowVideoForm` и callback-префикс `meowv`;
- выбор ровно одного референса из базы персонажей либо загрузка JPG/PNG/WEBP из Telegram;
- обязательный текст движения до 8000 символов;
- параметры `480p/720p`, `6/10 секунд`, форматы `9:16`, `16:9`, `1:1`, `2:3`, `3:2`;
- доступны `normal` и `fun`; `spicy` намеренно скрыт;
- перед постановкой задачи показываются параметры и расчётная себестоимость в USD и RUB;
- общий AI budget проверяется до enqueue;
- session-based `dedupe_key` защищает от двойной платной постановки;
- provider input содержит одно `image_urls`, `prompt`, `mode`, `duration`, `resolution`, `aspect_ratio` и `nsfw_checker=false`;
- готовый MP4 скачивается worker-ом и загружается в Telegram через `BufferedInputFile`;
- основной delivery использует `send_video(..., supports_streaming=True)`, при `TelegramBadRequest` выполняется fallback на оригинальный документ;
- лимит результата 50 МБ, timeout 120 секунд и три попытки скачивания;
- корневой экран `Мяу` теперь описывает рабочие ветки `Создать` и `Оживить`;
- добавлены unit-тесты UI, provider payload, стоимости, fallback-значений, конфигурации и доставки видео.

### Миграции и совместимость

Миграции PostgreSQL не требуются. Добавлена рекомендуемая переменная:

```env
KIE_GROK_IMAGINE_IMAGE_TO_VIDEO_MODEL=grok-imagine/image-to-video
```

Старый `KIE_GROK_IMAGINE_VIDEO_MODEL` используется только если содержит image-to-video id. Устаревшее значение `grok-imagine/text-to-video` автоматически игнорируется в пользу `grok-imagine/image-to-video`, поэтому существующий локальный `.env` не блокирует запуск после обновления.
