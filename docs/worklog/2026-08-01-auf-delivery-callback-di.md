## Перед началом

### Цель

Устранить критический инцидент, при котором callback повторной доставки завершался до выполнения обработчика из-за отсутствующих позиционных аргументов сервисов кошелька и покупки.

### Исходный контекст

После исправления общего callback-маршрута Ауф обработчик доставки получил расширенную сигнатуру из одиннадцати зависимостей. Часть совместимой цепочки продолжала вызывать его по прежнему девятиаргументному контракту, из-за чего aiogram фиксировал `TypeError` до проверки действия callback.

### Планируемый объём

- сделать две новые зависимости совместимыми и необязательными для старой callback-цепочки;
- передавать исходному fallback только его фактические девять зависимостей;
- добавить регрессионные тесты для обычного fallback и действия повторной доставки;
- не менять экономику, списания, provider calls и формат сохранённых задач.

### Критерии готовности

- обработчик доставки вызывается как с девятью, так и с одиннадцатью зависимостями;
- действие `deliver` не запускает новую генерацию;
- остальные callback-действия передаются исходному обработчику без лишних аргументов;
- CI подтверждает unit, type и архитектурные контракты.

### Риски и ограничения

Исправление сохраняет временную цепочку runtime installers. Полное устранение подмен обработчиков остаётся частью архитектурной работы по явному composition root.

## После завершения

### Фактически сделано

- `auf_wallet_service` и `auf_purchase_service` получили совместимые значения по умолчанию в обработчике доставки;
- исходный девятиаргументный обработчик больше не получает две чужие зависимости;
- добавлены два асинхронных регрессионных теста на fallback и повторную доставку;
- ветка перебазирована на `main` после слияния PR #526, чтобы CI проверял совместную callback-цепочку.

Миграции базы данных отсутствуют. Callback payload, сохранённые задачи и API провайдеров не меняются. Исправление обратно совместимо с девяти- и одиннадцатиаргументными вызывающими слоями.
