## Перед началом

### Цель

Исправить служебный экран балансов так, чтобы он использовал отдельный ключ только для чтения общего баланса аккаунта Byesu и не смешивал этот показатель с квотами отдельных API-ключей.

### Исходный контекст

Production-запрос к `https://byesu.com/dashboard/billing/subscription` возвращал `HTTP 401 Invalid token`. Обработчик скрывал конкретный статус под общей строкой `баланс временно недоступен`, а для авторизации сначала выбирал общий `BYESU_API_KEY`. В кабинете Byesu квоты ключей показываются отдельно и не являются общим балансом аккаунта.

### Планируемый объём

- добавить отдельную переменную `BYESU_BALANCE_API_KEY`;
- сохранить совместимость с существующим `BYESU_API_KEY` и профильными AI-ключами;
- различать безопасные причины недоступности баланса;
- уточнить подпись показателя в Telegram;
- добавить unit-тесты без реальных сетевых запросов и секретов.

### Критерии готовности

- отдельный ключ баланса имеет приоритет над общим облачным ключом;
- успешный ответ `balance_usd` отображается как долларовый баланс аккаунта;
- HTTP 401 не маскируется под общий временный сбой;
- токены и сырые ответы провайдера не выводятся в Telegram;
- целевые тесты и обязательные CI-проверки проходят.

### Риски и ограничения

- endpoint баланса требует действующий API-ключ того же аккаунта;
- изменение кода не добавляет секрет на production автоматически;
- квоты отдельных API-ключей не суммируются и не заменяют баланс аккаунта;
- production smoke возможен только после merge, обновления VPS и добавления секретной переменной.

### Миграции и совместимость

SQL-миграций нет. При отсутствии `BYESU_BALANCE_API_KEY` обработчик использует прежний порядок совместимости через `BYESU_API_KEY`, затем профильные AI-ключи для `byesu.com`.
