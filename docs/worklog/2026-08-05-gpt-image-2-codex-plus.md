# GPT Image 2 через Codex Plus

Дата: 2026-08-05

## Контекст

Ауф уже поддерживает несколько внешних моделей генерации изображений с
референсами, промтом, разрешением и соотношением сторон. Требовалось добавить
отдельный путь `GPT Image 2`, использующий существующий Hermes/Codex runtime,
авторизованный через подписку ChatGPT Plus, без отдельного OpenAI API key.

## Принятые продуктовые решения

- отображаемое имя модели: `GPT Image 2`;
- режим `Только текст` принимает 0 референсов;
- режим `Фото + текст` принимает от 1 до 5 референсов;
- пользователь не назначает роли изображениям: Каэль анализирует весь набор как
  общие референсы персонажа, одежды, окружения, композиции и деталей;
- промт ограничен 8000 символами и двумя сообщениями;
- служебные параметры, включая пропорцию, модель анализа и effort, хранятся
  отдельно и не уменьшают пользовательский лимит промта;
- пользователь выбирает GPT-5.6 Sol, Terra или Luna и effort
  `low`, `medium`, `high`, `xhigh` либо `max`;
- выполняется ровно один вызов встроенного `image_gen`;
- автоматическая перегенерация запрещена, задача создаётся с `max_attempts=1`;
- сетевые повторы доставки не запускают новую генерацию;
- выходной формат фиксирован как JPEG quality 95;
- доступен экспорт 1K, 2K и 4K;
- Telegram получает отдельный preview и исходный JPEG-документ;
- при наличии данных runtime сохраняются снимки лимитов Codex до и после задачи.

## Семантика 1K, 2K и 4K

Размер означает точные размеры итогового JPEG с сохранением выбранной пропорции.
Для 16:9 это 1024×576, 2048×1152 и 3840×2160 соответственно.

Встроенный ImageGen через подписку не предоставляет подтверждённый контракт
нативной генерации в точном 4K. Если исходник меньше выбранного уровня, Velvet
использует Lanczos scaling и умеренный UnsharpMask. Это увеличивает разрешение
файла и улучшает пригодность для публикации, но не выдаётся за появление новых
нативных деталей.

## Архитектура

Добавлен отдельный тип задачи `media.generate.codex_image`. Бот передаёт запрос
через защищённый Hermes coder router в проектный Codex runtime. Runtime создаёт
изолированный checkout, помещает референсы в закрытую папку задачи, передаёт
выбранный reasoning effort в `codex exec`, требует ровно один итоговый artifact и
удаляет временные входные файлы после завершения.

Image-run не получает GitHub token. Результат скачивается ботом, конвертируется в
целевой JPEG и отправляется пользователю. Feature flag выключен по умолчанию.

## Эксплуатация

Для включения нужны:

- `CODEX_IMAGE_ENABLED=true`;
- `CODEX_IMAGE_ROUTER_URL`;
- `CODEX_IMAGE_ROUTER_TOKEN`;
- актуальные `hermes-coder-router`, `hermes-coder-velvet` и host sandbox launcher.

После deployment обязателен live smoke на активной подписке Plus:

1. текстовая генерация 1K;
2. генерация с одним референсом;
3. проверка одного вызова генератора;
4. получение preview и JPEG-документа;
5. проверка снимков лимитов, если Codex возвращает их для этого запуска.

CI проверяет контракты, экспорт, маршрутизацию и упаковку, но не может доказать
доступность встроенного `image_gen` у конкретной живой подписки.
