## Перед началом

### Цель

Добавить `grok-imagine-video-1-5-preview` в существующий экран выбора видео-модели, не заменяя и не удаляя старый `grok-imagine/image-to-video`.

### Исходный контекст

В разделе `Мяу → Видео` уже выбираются Grok Imagine v1, Seedance 1.5 Pro и Wan 2.7. Старый Grok использует собственный provider contract с полем `mode` и отдельным внутренним alias. Новая версия Grok 1.5 принимает изображение, prompt, разрешение и длительность, но не должна подменять прежний маршрут, иначе уже поставленные в очередь задачи станут неоднозначными.

### Планируемый объём

- добавить отдельный доменный alias для Grok 1.5;
- добавить отдельный provider model id и переменные окружения;
- вывести два Grok отдельными кнопками в Telegram;
- дать Grok 1.5 выбор 480p/720p и длительности 2–15 секунд;
- сформировать новый payload без legacy-поля `mode`;
- сохранить сериализацию и восстановление старых задач Grok v1;
- добавить тесты UI, конфигурации, цены и границы Kie-клиента.

### Критерии готовности

- в списке видео-моделей одновременно видны Grok v1 и Grok 1.5;
- выбор одной модели не меняет provider id другой;
- Grok 1.5 отправляется как `grok-imagine-video-1-5-preview`;
- payload Grok 1.5 содержит `image_urls`, `aspect_ratio`, `resolution`, `duration` и не содержит `mode`;
- старый alias `grok_imagine_video` остаётся неизменным;
- tests, type check, Docker build и project notes contract проходят.

### Риски и ограничения

- текущий пользовательский поток принимает одно исходное фото, хотя provider допускает больше изображений;
- минимальная длительность интерфейса пока остаётся общей для расширенных видео-моделей и равна 2 секундам;
- ставки себестоимости вынесены в `.env` и требуют актуализации при изменении тарифов Kie;
- живая provider-генерация выполняется только после слияния и обновления серверного `.env`.
