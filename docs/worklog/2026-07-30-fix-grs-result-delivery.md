## Перед началом

### Цель

Исправить ситуацию, когда GRS-задача доходила до 100%, сохраняла URL результата, но пользователь не получал ни предпросмотр, ни исходный файл.

### Исходный контекст

`FriendlyKieGenerationWorker` переопределял надёжную доставку упрощённым вызовом `send_photo(photo=url)`. Telegram не всегда мог скачать временный URL GRS, ошибка поглощалась best-effort обработкой, а задача уже считалась завершённой.

### Планируемый объём

- скачивать результат GRS самим ботом;
- отправлять изображение как Telegram preview и оригинальный document;
- использовать существующие повторы скачивания и доставки;
- сохранить корректное имя провайдера в подписи;
- добавить безопасный повтор доставки уже завершённой задачи без новой генерации и списания;
- покрыть контракт тестом.

### Критерии готовности

- Telegram не получает внешний GRS URL как единственный источник изображения;
- результат сначала загружается в память и отправляется через `BufferedInputFile`;
- пользователь получает preview и оригинальный файл;
- повторная доставка использует сохранённые `result_urls` и не запускает провайдера заново;
- tests, type check, Docker build и project notes contract проходят.

### Риски и ограничения

- очень большой файл требует памяти на время загрузки и отправки;
- окончательно недоступный provider URL после исчерпания retry нельзя восстановить без повторной генерации;
- recovery-скрипт требует доступ к той же PostgreSQL и корректному Telegram token окружения.

## После завершения
