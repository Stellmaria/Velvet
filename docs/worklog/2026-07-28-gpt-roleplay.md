## Перед началом

### Цель

Подключить к Velvet отдельную текстовую модель для ролевой игры, поддержать GPT через OpenAI API и локальную модель через Ollama, а также обеспечить канон, историю и долговременную память между сообщениями.

### Исходный контекст

В проекте существовали vision-контур Ollama и маршрутизация локальных AI-моделей, но не было рабочего GPT-клиента, постоянных РЛ-сессий, истории, памяти и Telegram-команд.

### Планируемый объём

- отделить текстовые модели от vision-настроек;
- реализовать OpenAI Responses API, OpenAI-compatible и Ollama clients;
- добавить автоматический fallback;
- хранить сессии, канон, реплики и резюме в PostgreSQL;
- автоматически сворачивать старую историю;
- добавить Telegram-команды и тесты;
- сохранить функцию выключенной по умолчанию.

### Критерии готовности

- GPT выбирается через `AI_TEXT_PROVIDER=openai` без изменения vision-моделей;
- OpenAI-запросы используют Responses API и `store=false`;
- локальная Qwen может быть основной моделью или fallback;
- канон, резюме и последние сообщения входят в каждый ход;
- старые сообщения сворачиваются в память;
- РЛ включается отдельно для чата и пользователя;
- длинные ответы делятся по лимиту Telegram;
- command и architecture inventories остаются зелёными.

### Риски и ограничения

- качество и допустимый контент зависят от правил провайдера;
- OpenAI API требует отдельного оплачиваемого API-ключа;
- локальная 9B-модель на RTX 3050 Ti 4 ГБ может отвечать медленно;
- первая версия хранит одну активную историю на пару `chat_id + user_id`;
- live-запрос к реальному OpenAI API не выполняется в CI.
