## Перед началом

### Цель

Не считать кратковременный сетевой разрыв при `edit_message_text` окончательной ошибкой генерации и безопасно повторять только идемпотентное редактирование сообщения.

### Исходный контекст

Во время публикации прогресса Telegram иногда разрывает HTTP-соединение после отправки запроса. Worker получает `TelegramNetworkError`, хотя генерация продолжает выполняться. Обычные отправки нельзя автоматически повторять без разбора, поскольку потерянный ответ может привести к дублированию сообщения.

### Планируемый объём

- добавить ограниченные повторы для `EditMessageText`;
- сохранить отдельный retry budget для `GetMe`;
- не повторять `SendMessage` и другие неидемпотентные операции;
- считать `message is not modified` успешным результатом повторного редактирования;
- покрыть поведение асинхронными тестами.

### Критерии готовности

- временная ошибка `EditMessageText` повторяется с задержками 1, 2 и 4 секунды;
- обычная отправка после сетевой ошибки не повторяется;
- уже применённое редактирование не попадает в Error Center как ошибка;
- существующие повторы `GetMe` не меняются;
- tests, type check, Docker build и project notes contract проходят.

### Риски и ограничения

- повторяются только текстовые редактирования, другие методы Telegram намеренно остаются без общего автоматического retry;
- постоянная недоступность Telegram после исчерпания бюджета всё равно пробрасывается вызывающему коду;
- живая проверка зависит от фактического сетевого сбоя Telegram и не воспроизводится детерминированно в CI.

## После завершения

### Фактически сделано

- добавлен отдельный retry budget для `EditMessageText`;
- выбор задержек вынесен в `_retry_delays_for`;
- логирование сообщает тип повторяемого Telegram-метода;
- `TelegramBadRequest: message is not modified` после сетевой ошибки считается успешным завершением;
- `SendMessage` и прочие неидемпотентные методы не повторяются;
- добавлены тесты успешного повтора, уже применённого редактирования и отсутствия retry для обычной отправки.

### Миграции и совместимость

Миграции базы данных не нужны. Публичный интерфейс `ProtectedMediaBot` не изменён; новое поведение действует только внутри транспортного вызова Telegram.
