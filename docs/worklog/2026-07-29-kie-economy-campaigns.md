# Сессия: экономные кампании Kie до 50 попыток

## Перед началом

### Цель

Повысить вероятность получения результата до пятидесяти подтверждённых provider-попыток, не создавая параллельные платные дубликаты одной генерации и не повторяя уже оплаченную задачу после сетевого сбоя.

### Исходный контекст

После PR #367 Kie-задачи могли выполняться четырьмя worker-слотами и повторяться до одиннадцати раз. Повтор охватывал всю queue-задачу: референс загружался заново, provider task id не сохранялся сразу, а постоянные и временные ошибки обрабатывались слишком похоже. При потерянном ответе createTask существовал риск оплаченного дубликата.

### Планируемый объём

- повысить потолок AI task attempts с 20 до 50 отдельной миграцией;
- оставить четыре параллельных worker-слота для разных пользовательских кампаний;
- выполнять provider-попытки одной кампании строго последовательно;
- сохранять загруженные URL референсов в payload и повторно использовать их;
- сохранять active provider task id сразу после подтверждённого createTask;
- при перезапуске или timeout продолжать polling той же provider-задачи;
- создавать новую платную попытку только после подтверждённого state=fail;
- останавливать кампанию на первом success;
- не повторять автоматически постоянные и финансово неоднозначные ошибки;
- сохранять creditsConsumed и стоимость также для оплаченных failed-задач.

### Критерии готовности

- KIE_GENERATION_MAX_ATTEMPTS принимает значение 50;
- одна кампания не имеет более одной активной provider-задачи;
- сохранённый provider task id используется после повторного claim;
- референс не загружается заново между последовательными попытками;
- transient polling не создаёт новый createTask;
- подтверждённый provider fail запускает следующую попытку;
- потерянный/неподтверждённый ответ createTask останавливает автоповтор;
- первый success завершает campaign и не создаёт новые provider-задачи;
- tests, type check, Docker build и project notes contract проходят.

### Риски и ограничения

- без публичного callback endpoint потерянный ответ createTask нельзя надёжно восстановить, поэтому экономный режим останавливает такую кампанию вместо рискованного дубля;
- временные Kie upload URL могут истечь, поэтому ошибки expired/image URL очищают кэш и вызывают повторную загрузку референса;
- четыре разные кампании всё ещё могут одновременно расходовать баланс;
- actual_cost_rub остаётся локальной оценкой, а creditsConsumed является провайдерским фактом;
- Kie не документирует универсальную отмену уже принятой Market-задачи, поэтому внутри одной кампании не запускаются агрессивные параллельные дубликаты.
