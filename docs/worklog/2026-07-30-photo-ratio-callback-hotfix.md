## Перед началом

### Цель

Устранить production-ошибку aiogram при построении клавиатуры соотношений сторон `1:1`, `9:16` и других значений с двоеточием.

### Исходный контекст

`MeowCallback` использует стандартный разделитель aiogram `:`, а фото-flow передавал само соотношение сторон в поле `value` без кодирования. Вызов `CallbackData.pack()` отклонял значение `1:1` до показа клавиатуры.

### Планируемый объём

- безопасно кодировать соотношение сторон внутри callback;
- декодировать значение до проверки capability map и записи в FSM;
- не менять существующий callback-префикс и остальные кнопки;
- добавить регрессию для всех шести фото-моделей.

### Критерии готовности

- клавиатуры всех моделей упаковываются без `ValueError`;
- `1:1`, `9:16`, `21:9` и `auto` проходят обратное преобразование;
- provider request по-прежнему получает исходную запись с двоеточием;
- полный CI зелёный.

### Риски и ограничения

Исторический callback-протокол сохраняется. Исправление намеренно ограничено полем соотношения сторон и не меняет separator всего `MeowCallback`, чтобы старые активные кнопки продолжали разбираться.

## После завершения

### Фактически сделано

- добавлено callback-безопасное кодирование `1:1 → 1x1`;
- перед обработкой `photo_ratio` значение восстанавливается `1x1 → 1:1`;
- клавиатура соотношений сторон подменяется после установки основного фото-flow;
- добавлена регрессия упаковки клавиатур Nano Banana 2/Pro, Seedream 5 Pro, Qwen Image 2.0, Wan 2.7 Image и FLUX.2 Pro.

### Миграции и совместимость

Миграций базы нет. Callback prefix, action и структура persistent payload не меняются. Кодирование касается только поля `value` для действия `photo_ratio`.
