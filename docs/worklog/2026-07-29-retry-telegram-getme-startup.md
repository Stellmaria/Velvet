## Перед началом

### Цель

Не завершать всё приложение из-за единичного временного сетевого сбоя Telegram API во время обязательного стартового запроса `getMe`.

### Исходный контекст

После обновления приложение успешно выполнило резервное копирование и миграции, но первый запуск завершился с `TelegramNetworkError`, вызванным `ClientConnectorError` к `api.telegram.org:443`. Supervisor поднял процесс повторно через несколько секунд, после чего polling запустился штатно.

### Планируемый объём

- добавить ограниченные повторные попытки только для метода Telegram `GetMe`;
- использовать возрастающие паузы между попытками;
- не повторять автоматически отправку сообщений и другие запросы с неопределённым результатом;
- покрыть успешное восстановление, исчерпание попыток и отсутствие повторов для остальных методов тестами.

### Критерии готовности

- временный сетевой сбой `getMe` не завершает приложение после первой ошибки;
- выполняется не более пяти попыток;
- после исчерпания попыток исходная ошибка передаётся существующему fatal-handler;
- не-сетевые ошибки и сетевые ошибки других Telegram-методов сохраняют прежнее поведение;
- существующая защита приватных медиа и обработка устаревших callback не меняются.

### Риски и ограничения

Повтор ограничен методом `GetMe`, потому что он является безопасным чтением. Автоматический повтор отправки сообщений после сетевой ошибки мог бы создать дубликаты, если Telegram принял запрос, но ответ потерялся. Отключённая локальная Ollama в этот срез не входит; её замена серверной VL-моделью будет отдельной работой.

## После завершения

### Фактически сделано

- `ProtectedMediaBot` повторяет `GetMe` после `TelegramNetworkError`;
- настроено пять попыток с задержками 2, 4, 8 и 15 секунд;
- каждая повторная попытка записывается как предупреждение в обычный лог;
- после пятой неудачи ошибка передаётся существующему критическому обработчику;
- остальные Telegram-методы не получают автоматический повтор;
- добавлены три асинхронных unit-теста.

### Миграции и совместимость

Миграции PostgreSQL и новые переменные окружения не требуются. Поведение успешных Telegram-запросов не меняется. Ошибки токена, прав и других конфигурационных причин не маскируются повторами.

### Проверки

- изменённые Python-файлы прошли `py_compile`;
- добавлены тесты восстановления после двух сетевых ошибок;
- добавлен тест исчерпания всех пяти попыток;
- добавлен тест отсутствия повторов для `SendMessage`;
- полный CI должен подтвердить совместимость с установленной версией aiogram.

### PR и commit

- ветка: `agent/retry-telegram-getme-startup`;
- коммиты кода и тестов созданы через GitHub Contents API;
- draft PR создаётся после добавления этой обязательной записи worklog.

### Незавершённое

Локальный live-запрос к Telegram не выполнялся, чтобы не использовать production token вне рабочего окружения. Предупреждения отключённой Ollama остаются вне текущего исправления.

### Следующий шаг

Дождаться CI, слить PR и выполнить обычное обновление бота. При следующем кратком сетевом сбое запуск должен пережить его без CRITICAL-инцидента, если Telegram восстановится в пределах окна повторов.
