# Сессия: диагностика и восстановление OLLAMA_MODELS на диске E

- Дата: 2026-07-28
- ID: `2026-07-28-ollama-storage-diagnostics`
- Линия/фаза: Velvet Supervisor / локальный AI vision
- Статус: `завершено`
- Ветка: `agent/ollama-storage-diagnostics`
- Базовый commit: `ed5d09361ca243056297d635b2f06fed401968de`

## Перед началом

### Цель

Восстановить удалённый доступ к ранее перенесённым моделям Ollama на диске `E:` и исключить скачивание второго набора моделей в неправильный каталог.

### Исходный контекст

После перезагрузки Windows:

- задача `VelvetSupervisor` и Ollama запускались успешно;
- `ollama list` возвращал пустой список;
- pose extractor получал `HTTP 404 model not found` для старой HF-модели и `qwen3-vl:8b`;
- ранее модели переносились с системного диска через `OLLAMA_MODELS=E:\OllamaModels`;
- было неизвестно, лежат ли `blobs` и `manifests` непосредственно в `E:\OllamaModels` или во вложенном `E:\OllamaModels\models`;
- существующие быстрые кнопки не показывали команды состояния и полного восстановления Ollama.

### Планируемый объём

- расширить `Ollama: состояние vision` диагностикой процесса, project `.env`, User и Machine environment;
- проверить только два фиксированных каталога на `E:`;
- определить корректный корень по наличию `blobs` и `manifests`;
- записывать найденный путь в project `.env` и User Environment;
- перезапускать Ollama с выбранным хранилищем до загрузки модели;
- прекращать восстановление при неоднозначной повреждённой структуре;
- добавить быстрые кнопки состояния и полного восстановления;
- добавить regression-тесты и документацию.

### Критерии готовности

- диагностика не читает и не выводит секреты `.env`;
- Telegram не может передать произвольный путь;
- корректно различаются `E:\OllamaModels` и `E:\OllamaModels\models`;
- неизвестные строки `.env` сохраняются;
- дубли `OLLAMA_MODELS` удаляются;
- при существующей неправильной структуре скачивание не начинается;
- операции остаются фиксированными argv-командами без shell;
- обязательные CI-проверки проходят.

## После завершения

### Фактически сделано

- `velvet_supervisor.ollama_recovery` получил модель `StorageLayout` и безопасный инспектор каталогов;
- команда состояния показывает:
  - process `OLLAMA_MODELS`;
  - project `.env`;
  - User и Machine environment Windows;
  - структуру обоих разрешённых каталогов `E:`;
  - стандартный каталог профиля пользователя;
  - число blob и manifest файлов;
  - рекомендуемый путь;
- восстановление выбирает корректный вариант на `E:` по числу manifest и blob файлов;
- выбранный путь атомарно записывается в project `.env` и User Environment;
- работающий `ollama.exe` останавливается фиксированным `taskkill.exe` с `shell=False`;
- новый `ollama serve` запускается с выбранным `OLLAMA_MODELS`;
- после переключения проверяется список моделей;
- только затем выполняются настройка `AI_VISION_*`, `ollama pull qwen3-vl:4b` и проверка capability `vision`;
- при найденных, но некорректных каталогах на `E:` операция завершается до скачивания;
- в безопасной консоли добавлены быстрые кнопки состояния и восстановления Ollama.

### Безопасность

- разрешены только `E:\OllamaModels` и `E:\OllamaModels\models`;
- пользователь Telegram не передаёт путь, имя модели или параметры процессов;
- shell не используется;
- команда остановки фиксирована на `ollama.exe`;
- секретные и неизвестные строки project `.env` сохраняются;
- изменяются только `AI_VISION_*` и `OLLAMA_MODELS`.

### Тесты

Добавлены проверки:

- каталог без `manifests` считается невалидным;
- при двух валидных вариантах выбирается каталог с большим числом manifest-файлов;
- невалидные кандидаты возвращают отсутствие рекомендации;
- запись `OLLAMA_MODELS` сохраняет токены и пользовательские настройки;
- дубли переменной удаляются;
- быстрые кнопки состояния и полного восстановления присутствуют;
- прежние capability и fixed-argv контракты остаются защищены.

### Миграции и совместимость

Миграции PostgreSQL не требуются. Форматы API Supervisor и callback-контракт Telegram не меняются. Используются существующие действия `status` и `repair`, поэтому старые текстовые команды остаются совместимыми.
