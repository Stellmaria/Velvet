# Исправление таймаута восстановления Ollama

- Date: 2026-07-28
- ID: supervisor-ollama-repair-timeout
- Line/phase: Supervisor / локальные AI-модели
- Status: завершено
- Branch: agent/ollama-repair-timeout
- Base commit: main

## Перед началом

### Цель

Устранить ложное завершение операции `Ollama: восстановить набор моделей` с кодом 124, когда загрузка крупной модели фактически заканчивается успешно, но общий лимит Supervisor прерывает последовательную установку всего набора.

### Контекст

Операция длилась 1401 секунду, вывела `writing manifest` и `success`, а установленная uncensored vision-модель появилась в `ollama list`. Однако общий таймаут команды был короче времени, необходимого для последовательной установки четырёх моделей.

### План

1. Дать операциям установки и восстановления Ollama отдельный безопасный лимит 7200 секунд.
2. Не расширять таймаут остальных команд Supervisor.
3. Обновить устаревшие названия операций, всё ещё упоминавшие одну модель `qwen3-vl:4b`.
4. Удалять ANSI-последовательности и управляющие возвраты каретки из сохранённого вывода.
5. Добавить регрессионные тесты.

### Риски

- Нельзя превращать Telegram-консоль в произвольный shell.
- Нельзя ослаблять фиксированный allowlist команд.
- Длинный лимит должен применяться только к заранее определённым операциям Ollama.

## После завершения

### Выполнено

- В `RemoteCommandSpec` добавлен флаг применения общего ограничения таймаута.
- Для `ollama pull` и `ollama repair` установлен отдельный лимит 7200 секунд без обрезания общим лимитом Supervisor.
- Остальные команды сохраняют прежний общий предел.
- Названия операций обновлены до `состояние/настроить/установить/проверить/восстановить набор моделей`.
- Старые ключи и aliases сохранены для совместимости.
- ANSI escape-последовательности и carriage return очищаются до сохранения результата и отправки в Telegram.
- Добавлены тесты на расширенный таймаут, новые названия и очистку терминального вывода.

### Проверка

- Синтаксис изменённых Python-файлов проверен локально перед публикацией.
- Полный набор CI запускается pull request после создания.

### Результат

После обновления Supervisor повторная операция восстановления сможет пропустить уже установленную 8B-модель, зарегистрировать fallback 4B и скачать text 9B без ложного таймаута через 1400 секунд.
