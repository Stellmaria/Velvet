## Перед началом

### Цель

Гарантировать, что после успешной видеогенерации пользователь получает исходный MP4 отдельным Telegram-файлом без сжатия, а не только обычный видеопредпросмотр.

### Исходный контекст

В текущем `main` видеопредпросмотр отправлялся первым через `send_video`, после чего тот же payload отправлялся документом. Если второй вызов Telegram завершался ошибкой, внешний best-effort обработчик только записывал её в технический лог. Пользователь видел обычное видео и не получал исходный файл. Предыдущее исправление находилось в PR #393 поверх незалитого PR #390, поэтому обновление бота из `main` его не содержало.

### Планируемый объём

- создать независимый hotfix от актуального `main`;
- отправлять исходный MP4 первым через `send_document`;
- включить `disable_content_type_detection=True`;
- отправлять видеопредпросмотр отдельным вторым сообщением;
- изолировать ошибки документа и предпросмотра;
- уведомлять пользователя о частичной доставке;
- не запускать повторную платную генерацию из-за ошибки Telegram;
- покрыть все видеомодели текущего `main` регрессионными тестами.

### Критерии готовности

- Grok Imagine v1 отправляет документ и предпросмотр;
- Grok Imagine Video 1.5 отправляет документ и предпросмотр;
- Seedance 1.5 Pro отправляет документ и предпросмотр;
- Wan 2.7 отправляет документ и предпросмотр;
- документ отправляется раньше предпросмотра;
- у документа установлен `disable_content_type_detection=True`;
- ошибка документа не блокирует предпросмотр;
- пользователь получает явное предупреждение о недоставленном исходнике;
- CI проходит.

### Риски и ограничения

- Telegram по-прежнему ограничивает размер загружаемого файла и может отклонить слишком крупный результат;
- текущий downloader ограничивает исходный результат размером 50 МБ;
- hotfix исправляет доставку, но не изменяет ограничения Kie, GRS или Telegram;
- статистика стоимости и времени остаётся в отдельном PR #393 и не входит в срочный hotfix.
