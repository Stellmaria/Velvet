# Память сущностей

## Три слоя

| Слой | Назначение | Срок | Источник истины |
|---|---|---|---|
| Рабочая память | Текущий prompt, результаты и план | Один запуск | Runtime context |
| Короткая память | Сжатое состояние незавершённой задачи | До завершения/TTL | Session или task ledger |
| Долговременная память | Подтверждённые устойчивые факты и правила | Versioned | Git + Brain Vault |

SOUL не является памятью: это стабильная личность. AGENTS не является историей:
это действующий контракт. Секреты, полные диалоги, необработанные логи,
персональные данные и догадки не являются допустимой памятью.

## Запись

Сущности не записывают наблюдение напрямую в канонический Vault. Они создают
`memory_candidate` по schema `memory-proposal.schema.json` с источником,
уверенностью, областью и сроком. Каэль удаляет дубли и проверяет безопасность;
долговременное изменение делает профильный кодер через GitHub PR. Владелец
сохраняет контроль над merge.

Memory принимается, только если факт:

- пригодится в нескольких будущих задачах;
- проверяем по указанному source/evidence;
- не дублирует действующие SOUL, AGENTS или project notes;
- не содержит секретов и лишних персональных данных;
- относится ровно к одной разрешённой области.

## Чтение и забывание

Сначала извлекаются только records нужной сущности, проекта и задачи. Конфликт
memory с Git/runtime evidence помечается как stale и не используется. Временный
факт получает `expires_at`; закрытая task memory удаляется либо агрегируется.
Memory seed устанавливается только при отсутствии живой runtime memory и никогда
не перезаписывает накопленное состояние.
