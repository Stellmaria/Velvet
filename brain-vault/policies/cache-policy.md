# Кэширование контекста

Кэш экономит задержку и вычисления, когда начало prompt побайтно стабильно.
Это ускорение, а не память: кэш не гарантирует сохранение факта между сессиями.

## Стабильный префикс

Порядок должен оставаться постоянным: platform rules → SOUL → compiled AGENTS
→ versioned skills. В эти файлы нельзя добавлять timestamps, session IDs,
случайные значения, текущие логи или task-specific текст.

Динамические данные располагаются после стабильного префикса: выбранная memory,
handoff, диалог и результаты инструментов. Изменение любого байта раннего слоя
может инвалидировать весь последующий prefix cache.

## Инвалидация и доказательство

- Git commit и `brain_version` определяют версию источника.
- `context-manifest.json` хранит SHA-256 каждого source и output.
- Runtime smoke проверяет manifest и роль/проект, а не только наличие файла.
- Pack сначала собирается и проверяется в новом каталоге. Active files
  заменяются атомарно по одному, а manifest — последним; preflight не запускает
  runtime, если установка осталась частичной.
- Секреты и mutable runtime state никогда не входят в кэшируемый pack.

Не оптимизируй кэш ценой правильности: необходимое ограничение обновляется
сразу, даже если это инвалидирует префикс.
